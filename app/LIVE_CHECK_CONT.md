# 実機確認 継続チャット最小版（S-P）

対象: ブランチ `feature/org-engine`（C1〜C6）。設計 `app/DESIGN_CONT.md`、レビュー `app/REVIEW_CONT.md`。実機（Windows 11・実Codex 0.162.1）で行うのはユーザー。
導入（NSIS の上書きインストール）は `app/LIVE_CHECK_ORG.md` の 0-1 と同じ。**既存の通常チャットでそのまま確認できる**（組織実行は使わない）。
記録: 項目番号ごとに ○／×／△。×・△は「何をしたら何が出たか」を1行。

## 0. 先に知っておくこと

- 使う場所: **一般チャット**（作業フォルダなし）で試す。worktree に結び付いたチャット・組織実行のチャットは、引き継ぎの対象外（理由が出るのが正しい）。
- 引き継ぎは**あなたが押したときだけ**起きる。AgentDock が自動で新しい thread を作ったり送ったりすることはない（これが破れていたら要報告）。
- 古い thread は消えない。一覧では隠れるだけで、チャット画面の上の［表示］で読める。
- 目的メモは「その thread で最初の送信・メモを変えた後・Codex が会話を圧縮した後」だけ依頼に添わる（毎回ではない）。依頼の上に「資料」の折りたたみ行が出る。
- 文脈の使用率は Codex が教えてくれた値だけを出す。取れなければ「未取得」（推定しない）。

## 1. 確認項目

### K1. 使用率の表示（値の確からしさ）

操作: 一般チャットを新しく作り、数往復する。入力欄のまわりの「文脈 N%」を見る。可能なら Codex 側（VS Code 拡張、または CLI の `/status`）の残量とも比べる。

期待: 往復を重ねると%が上がる。Codex 側とおおむね一致（大きく違えば要報告。この変換は推測で入れたため）。取れないときは「未取得」で、%を作らない。接続を切った後は「前回の値」と分かる表示になる。

### K2. 閾値の案内と圧縮

操作: 長い文章（数千字）を貼って往復を重ね、70% と 90% の表示、Codex の自動圧縮が起きるかを見る。

期待: 70% 以上で入力欄の上に案内行（「引き継いで送信」を勧める）が出る。送信ボタンの文言が「引き継いで送信」に変わる。「このthreadで続ける」で通常の送信に戻り、案内が消える（次に90%以上になれば再び出る）。圧縮が起きたら「圧縮後・未取得」と出て、次の応答で下がった値に変わる。圧縮が起きない場合は、起きなかったと記録するだけでよい（引き継ぎは手動でも試せる。K4 へ）。

要報告: 案内が出ない（値が取れているのに）／推定の%が出る／圧縮後に古い%がそのまま出る。

### K3. 目的メモ

操作: ヘッダーの「…」または上部メニューの「目的メモ…」で、例「このチャットは会議の議事録用。見出しは『決定事項／TODO／論点』。丁寧語で簡潔に。」を保存。1通目を送信→2通目を送信→メモを少し直して3通目を送信。

期待: 1通目と3通目の依頼にだけ「資料」の折りたたみ行が付き、2通目には付かない。AI の返事がメモの様式に従う。

### K4. 引き継ぎ（新しい thread へ）

操作: 案内行の「資料を見る」で、送られる資料（目的メモ＋直近の往復）の中身を確認する。依頼文を書いて「引き継いで送信」を押す。

期待: 新しい thread で応答が返る。**左一覧は1行のまま**（古い thread は隠れる）。会話の上に薄い区切り線「ここから新しい thread（日時 に引き継ぎ）」。前の会話は［表示］を押すと読める（読取り専用、コピーだけ可）。依頼は利用者の文だけが吹き出しになり、資料は折りたたみ行。

要報告: 一覧に同じ会話が2行出る／前の会話が消える／勝手に送られる／送信が二重になる。

### K5. 引き継ぎ後の品質

操作: K4 の直後に、直前の話題に触れる質問（「さっきの決定事項をもう一度まとめて」）をする。

期待: 目的メモの様式と直近の話題を踏まえた返事になる。悪い場合は、どこが落ちたか（様式・話題・固有名詞）を記録して報告（往復数・上限を調整する材料）。

### K6. 作業領域の引き継ぎ

操作: 一般チャットで AI にファイルを作らせ（例「memo.txt を作って今日の日付を書いて」）、引き継ぎ、続けて「memo.txt に1行足して」と頼む。

期待: 新しい thread からも同じファイルが見え、編集できる。

### K7. 止める条件

操作: 承認待ち、実行中、送信待ちのキューあり、子エージェント作業中、のそれぞれで引き継ぎを試す。

期待: 「引き継いで送信」にならず、止まっている理由が出る（子の状態が未確認なだけのときは、注記つきで送れる）。

### K8. 引き継ぎ中の切断・再起動

操作: 引き継ぎの送信直後に Codex（`codex.exe`）をタスクマネージャーで終了。AgentDock を再接続、または再起動。

期待: **自動で再送されない**。照合の後に状態が確定する（届いた／受理不明のまま、のどちらかを正直に表示）。一覧に同じ会話が2行出ない。

要報告: 勝手に再送／done・failed に置き換わった／2行出る。

### K9. 削除

操作: ①先頭（今の）thread を削除する。②（可能なら）ドックや通知から以前の thread を開いて削除しようとする。

期待: ①削除確認に「以前の thread N 本は残ります」の文言。削除すると、直前の thread が一覧に戻る。②今の thread が作業フォルダを使っているときは「削除できません」と理由が出て、削除ボタンが無効（今の thread のファイルが消えない）。

要報告: ②で削除できてしまい、今の thread のファイルが消えた。

### K10. 検索・コピー・エクスポート・再送

操作: Ctrl+F で検索、依頼のコピー、エクスポート、「編集して再送」。

期待: 検索は開いた資料の枠も対象。未読込みの古い thread がある注記が出る。コピー・再送の初期値は**利用者の文だけ**（資料なし）。エクスポートは資料が1行に置き換わり、冒頭に「以前の thread が N 本あります」。

### K11. 組織実行・通常チャットの回帰

操作: 継続チャットを使っていない普通のチャットで、送信・承認・中断・履歴が今までどおり動くことを軽く確認。

期待: 目的メモを書いていないチャットには何も添わらない。変化なし。
