# DESIGN_CHANGES_UI — 「変更を確認」画面の作り直し（v0.1, 2026-10-13）

対象: `ui/ChangesDialog.tsx`（ChangesBody・RevertBody）、`ui/revertView.ts`、`ui/RepoRecordPanel.tsx`、`ui/Dialogs.tsx`（"changes"/"revert"）、`styles.css`。
ホスト（rules/baseline.rs・preview_revert・revert_changes）と判定は**変えない**。見た目と操作の順序だけを変える。

前提の訂正: 戻す方式は正本1.2以降「Git基準の控え」（2026-10-10合意。旧「Codex報告の差分の逆適用」は置換済み）。本書は現行方式に従う。

## 1. 現状

### 1.1 フロー

- 入口: 「…」メニューに「変更を確認…」（diff）と「変更を戻す…」（revert）の2つ。別々のダイアログを開く。
- 変更の確認（ChangesBody）
  1. タブ「この会話の変更（記録）」／「Gitの現在の差分（HEAD比較）」。
  2. 上から: チャット名、未確認の文、「コミット・ブランチ切替の後は控えへ戻せません」（常時）、About、控えがない帯、所有者違いカード（①〜④）、「対象」select（`turn 1a2b3c4d…（終了時の控えなし）［同時作業あり］`）、取得失敗の帯、notes、表（種類・ファイル・追加・削除・turn ID）、その下に差分（最大320px）。
  3. フッター「変更を戻す…」→ **別ダイアログへ切替**（選択を引き継がない）。控えなしでは無効、理由はtitleだけ。
- 変更を戻す（RevertBody）
  1. 説明文、未確認、About、控えがない帯、「戻す範囲」select（turn X 以降）。
  2. 計画（読むだけ）→ ファイルごとのカード: 「戻せる／要確認／止める」、☑戻す、要確認は「別の変更も含めて控えの内容に戻す」、理由行、後続turn。**差分は見られない**。
  3. 「選んだ N 件を戻す…」→ 確認1段目 → 強制ありなら2段目 → 実行。
  4. 結果が一覧を置き換える。「もう一度確認する」「計画を作り直す」。

### 1.2 状態と画面の出し分け

|状態|変更の確認|変更を戻す|
|---|---|---|
|Gitなし・控えオフ・所有者違い・控えを取れなかった|帯（理由1本）＋所有者違いは案内カード。主ボタン無効|帯。計画は空か失敗|
|実行中のturn|turn選択肢に「作業中（途中の状態）」|ホストが止める（作業中は強制不可）|
|終了未確認（切断・再起動）|「終了時の控えなし」|要確認（強制のみ）|
|turnの間・後に別の変更／同時作業|［同時作業あり］|要確認|
|HEAD変化・Git操作の途中・対象外・作業フォルダ外|—|止める（強制不可）|
|戻し済み|表に「✓戻し済み」|止める（戻し済み）|
|受理不明の区間|turnに対応づくまで選択肢に出ない|同左|
|取得失敗|「取得できませんでした: …」|赤帯（計画を作れない）|
|Git（HEAD比較）タブ|表と差分のみ、戻すボタンなし|—|

### 1.3 ユーザーの目的

1. 今の依頼で何が変わったかを見る（ファイルと差分）。
2. 気に入らないファイルだけ取り消す。
3. どの依頼の前まで戻すかを選ぶ。
4. （たまに）チャットに関係なく未コミットの差分全体を見る。

## 2. 分かりにくさの原因

1. **見る画面と戻す画面が別**。戻す画面で差分が見えず、選択も引き継がない。
2. **範囲の意味が2つ**。「対象」＝そのturnだけ、「戻す範囲」＝そのturn以降。同じ形のselectで意味が違う。
3. **依頼をturn IDで示す**。`turn 1a2b3c4d…` は何を頼んだかと結びつかない。
4. **内部用語が前面**: 控え・控え基準・turn・区間・計画・強制・HEAD比較。
5. **帯と段落の積み重ね**（最大7段）。一覧と差分が押し下げられ、差分は320px。常時の注意文は該当しないときも出る。
6. **区分3種×チェックの意味2種**。カードの文量がまちまちで、選択を一望できない。
7. **無効の理由がtitleだけ**。
8. **確認が最大2段＋結果で一覧が消える**。
9. Gitタブが対等に並び、「このチャットの変更」との違いが長いラベル頼み。

## 3. 新しい画面（基本形）

### 3.1 方針

- **1つの画面で「見る→選ぶ→戻す」**。「変更を確認…」「変更を戻す…」はどちらもこの画面を開く（台帳 id はそのまま）。
- 左＝ファイル一覧（チェック＝戻す対象）、右＝差分。上に「依頼」の選択と件数、下に主ボタン1つ。
- 依頼は**ユーザーの発言の先頭**で示す。turn ID は title とコピーにだけ残す。
- 範囲の意味は1つ: 「この依頼で変わったファイル」を表示し、戻すとそのファイルは**この依頼の前の内容**になる。後の依頼の変更も一緒に戻るファイルは印で示す（`includesTurns`）。
- 状態は**色付きの印**で伝え、理由は選んだファイルの右ペイン上部に1行で出す（カードの文を一覧に並べない）。
- 帯は**1本の枠**（状態スロット）に優先順で1つだけ。

### 3.2 ワイヤーフレーム（このチャット）

```
┌ 変更を確認 ───────────────────────────────────── [未確認] ─ × ┐
│ 依頼 [▾ #4「ログイン画面のエラー表示を直して」 10:42 ]   (このチャット|Git（HEAD比較）)│
│ 4 ファイル  +128 −31                                                  │
│ ┌状態スロット（必要なときだけ1本）──────────────────────────────┐│
│ │⚠ 作業フォルダがGitリポジトリではないため…            [再確認] ││
│ └────────────────────────────────────────────┘│
│┌──────────────────────┐┌──────────────────────────────┐│
││☐ すべて              ││ M src/login.tsx   +40 −12          ││
││☑ M src/login.tsx  +40−12 ││ ◆要確認  turnの後に別の変更         ││
││☐ A src/err.ts     +88 −0 ││          ☐ それでも戻す             ││
││  ◆ src/api.ts  +0 −19 要確認││ ↺ 後の依頼の変更も戻ります（2）      ││
││  ■ assets/logo.png  戻せない││──────────────────────────────││
││  ✓ README.md    戻し済み ││ @@ -10,7 +10,9 @@                  ││
││                       ││ -  const msg = err                  ││
││                       ││ +  const msg = formatError(err)     ││
│└──────────────────────┘└──────────────────────────────┘│
│ ▸ この操作について                                                    │
├──────────────────────────────────────────────────┤
│                                   [閉じる]  [1 件を戻す…]（赤ではない主ボタン）│
└──────────────────────────────────────────────────┘
```

- 依頼セレクタ（`<select>`、新しい順）: 「すべての依頼」＋各依頼「#n 発言の先頭30字 時刻」。発言が手元にない依頼は「#n 時刻」。終了未確認・作業中・同時作業は末尾に短い印（`…`／`●作業中`／`⇆`）。控えを取れなかった依頼は選択肢に出すが無効（`disabled`、末尾に「記録なし」）。
- 既定の選択: **最新の依頼**。見出しは「N ファイル  +a −d」（Known が未取得なら「未確認」、0で代用しない）。
- 出所の切替は小さな2択（セグメント）。Gitのときは依頼セレクタ・チェック・主ボタンを出さない。

### 3.3 ファイル行

|印|意味（verdict）|チェック|行の右|
|---|---|---|---|
|種類アイコン A/M/D/R（色: 追加=緑、削除=赤、変更=青、移動=灰）|ChangedFile.kind/moveTo|—|`+a −d`、バイナリは「バイナリ」|
|（印なし）|revertible|可。既定オフ|—|
|◆ 要確認（黄）|needsOverride|一覧では**押せない**。右ペインの「それでも戻す」で入る（入ると☑と◆が並ぶ）|「要確認」|
|■ 戻せない（灰）|blocked（戻し済みを除く）|なし|「戻せない」|
|✓ 戻し済み（緑・淡色）|`reverted` または blocked:alreadyReverted|なし|「戻し済み」|
|✕ 失敗（赤）|直前の実行の failed|なし（再確認後に復帰）|「失敗」|
|？（灰）|計画を取れない・計画に無いファイル|なし|「未確認」|

- 「☐ すべて」は revertible だけを対象にする（要確認は含めない）。
- 行のクリック＝右に差分、チェックのクリック＝戻す対象。キーボードは↑↓で行移動、Spaceでチェック。

### 3.4 右ペイン（差分）

1. 見出し: 種類アイコン・パス（移動は `a → b`）・`+a −d`。
2. 理由行（要確認・戻せない・失敗のときだけ）: 印＋`BLOCK_LABEL` の短いラベル。詳細（ホストの message）は行の title と、行を押すと開く `<details>`（既存文のまま）。要確認は複数理由を固定順で全部出す（落とさない）。
3. 要確認のときだけ「☐ それでも戻す」。
4. `includesTurns` があれば「↺ 後の依頼の変更も戻ります（n）」（title に該当依頼の名前）。
5. 差分本文（既存 DiffText。高さは右ペインいっぱい）。

### 3.5 状態スロット（1本だけ。上から最初に当たったもの）

1. 一覧の取得失敗（赤）「取得できませんでした: …」＋[再確認]
2. 控えがない理由 `noBaselineReason`（黄）。このとき一覧は Git 以外空、チェック列・主ボタンを出さない
3. 所有者違い（黄）: RepoRecordPanel を**1行表示**（太字の見出し文＋[記録する][記録しない]、許可済み・記録しないの一行もここ）。①〜④の案内は「対処のしかた」の `<details>` に畳む（文は既存のまま）
4. 計画（戻せるかの判定）の取得失敗（黄）「戻せるか確認できませんでした: …」＋[再確認]。一覧と差分は見られる、チェックは出さない
5. 直前の結果（成功=情報、一部のみ=赤）「n 件を戻しました」／「一部のみ戻しました（戻せた n・戻せなかった m）」＋[戻す前の内容]（控えの場所。パスは title、押すとフォルダを開く既存操作）
6. `list.notes`（淡色の1行。複数は「・」で連結）

- 「コミット・ブランチ切替の後は控えへ戻せません」の常時表示は廃止。該当時は各ファイルの「戻せない: HEADが変わった…」で出る（根拠は消えない）。
- 「未確認」（OpCapability.verification）は見出し右の `[未確認]` タグに移す。title に既存の文。
- 「この操作について」は1つに統合（NOTE_BASELINE と RevertBody の About を順に）。

### 3.6 戻す（確認は1か所）

主ボタン: 「n 件を戻す…」（選択0件のときは出さない。無効にして title だけ、はしない）。押すとフッター上に ConfirmBlock を出す。

```
┌ 戻す確認 ─────────────────────────────────────┐
│ 次の 3 件を「#4 ログイン画面の…」の前の内容に戻します             │
│  src/login.tsx  ↺2   src/err.ts（削除されます）                    │
│ ┌ ◆ 別の変更も消えます（1）────────────────┐       │
│ │ src/api.ts  ・turnの後に別の変更                │       │
│ └──────────────────────────────┘       │
│                      [やめる]  [3 件を戻す]（危険・赤）         │
└────────────────────────────────────────┘
```

- 要確認を含むときは赤枠の小区画で分けて列挙し、危険ボタンを「別の変更も含めて 3 件を戻す」にする。
- 実行前に計画の期限（`expiresAt`）が切れていたら、同じ paths で previewRevert を取り直し、**選んだファイルの判定が1件でも変わっていたら実行せず**一覧へ戻す（変わった行を強調）。変わっていなければそのまま実行。
- 実行中は一覧・チェック・セレクタを無効、ボタンは「戻しています…」。
- 実行後は一覧を置き換えない。結果を状態スロット5に出し、一覧と計画を取り直す（成功・失敗・例外のどれでも）。失敗したファイルは ✕ と理由。例外は赤帯で、成功とは書かない。

### 3.7 狭い画面（UI-5のブレークポイント）

左右を上下に。一覧のみ表示 → 行を押すと差分に切替（左上に「← 一覧」）。主ボタンとConfirmBlockは下に固定。

### 3.8 文言（ラベルだけ。説明段落は増やさない）

|旧|新|
|---|---|
|変更の確認／変更を戻す（ダイアログ名）|変更を確認（1つ）|
|この会話の変更（記録）／Gitの現在の差分（HEAD比較）|このチャット／Git（HEAD比較）|

|別の変更も含めて控えの内容に戻す（確認が必要）|それでも戻す|

### 3.9 合意事項との照合

|合意|本案|
|---|---|
|戻すのはユーザーが押したときだけ・自動で戻さない|チェック既定オフ、確認の後だけ実行。期限切れで判定が変われば実行しない|
|帰属不明は止めて理由を示し、選べば別の変更も含めて戻せる（2段目の確認）|一覧では選べない→右ペインで理由を見て「それでも戻す」→確認で別区画に列挙し危険ボタン名を変える（選択点1）|
|強制できないもの（HEAD・Git操作中・対象外・外・戻し済み・作業中）|「戻せない」でチェックなし。判定はホストのまま|
|書き換え前の内容を控えに残す・自動削除しない|変更なし（結果に「戻す前の内容」）|
|取得不能・通信断を成功にしない、未確認を0で代用しない|取得失敗は赤／黄の帯、行は「未確認」、一部のみは赤|
|根拠表示を消さない|理由ラベルは全件、詳細文は title と details に残す。未確認タグ・About も残す|

## 4. 別案（要点のみ）

- **A: 依頼タイムライン型** — 左に依頼を縦に並べ、その下にファイル。時点は分かりやすいが一覧が長くなる。

## 6. 実機確認項目

1. 依頼2回でファイル変更 → 最新の依頼が選ばれ、件数・+/−・差分、依頼名は発言の先頭。
2. 1件チェック →「1 件を戻す…」→ 確認 → 一覧に「戻し済み」、帯に「1 件を戻しました」。
3. 古い依頼を選ぶ → 後でも変えたファイルに「↺」。戻すと後の変更も消える。
4. エディタで手で変更 →「◆要確認」。右の「それでも戻す」で入り、確認に別区画と危険ボタン名。
5. コミット後 →「■戻せない（HEADが変わった）」。常時の注意文は出ない。
6. 確認中に期限切れ＋ファイル変更 → 実行されず、変わった行が強調。
7. Gitなし／控えオフ／所有者違い → 帯1本、チェック列と主ボタンなし。所有者違いは1行＋「対処のしかた」。
8. Git（HEAD比較）→ セレクタ・チェック・主ボタンが消える。
9. 「変更を戻す…」からも同じ画面。狭い画面で一覧⇄差分。ダークで印が読める。

## 7. 選んでほしい点

1. **要確認ファイルの選び方と確認**
   - (a) 推奨: 右ペインで理由を見て「それでも戻す」→ 確認は1か所（別区画で列挙＋危険ボタン名の変更）。合意の「2段目の確認」を「理由を見て選ぶ＋確認」と読む。
   - (b) 現状どおり、要確認を含むときだけ確認を2回出す。
2. **チェックの既定**
   - (a) 推奨: すべてオフ（見るのが主目的。戻すときに選ぶ）。
   - (b) 「戻せる」ものは最初からオン（現状と同じ）。
3. **入口**
   - (a) 推奨: 基本形のみ（メニューの2項目が同じ画面を開く）。
   - (b) 別案Bも入れる（会話の依頼末尾に「変更 n」チップ）。

正本 §3.14 #1 のタブ名（「控え基準」）を画面で「このチャット」と表示する点は、採用時に正本の表記を版更新で合わせる。
