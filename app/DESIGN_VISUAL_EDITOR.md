## 1. 設計の結論と決定状態

目標は「画面を見る → 要素を選ぶ → 指示を送る → 自動修正された画面を見る → 採用／再修正／元に戻す」。手作業でDOMやCSSを書き換えるWYSIWYGではなく、選択情報を添えて既存AIチャットからソースを編集する機能とする。

|項目|状態|設計|
|---|---|---|
|01 配置|利用者決定|左: 既存情報、中央: プレビュー、右: 既存チャット|
|02 対象|利用者決定|ローカルHTMLファイル。利用者指定の開発サーバーURLは初期対象外|
|03 選択|利用者決定|単一・複数・親要素選択|
|04 指示|利用者決定|自由文＋簡易メニュー。送信前に選択情報を添付|
|05 実行|利用者決定|AIが自動修正し、その後に利用者が結果確認。Git自動コミットなし|
|06 編集範囲|**推奨・未決定**|利用者が確認したプロジェクトルート内で、HTMLと関連CSS／JSを自動検出。検出候補と実際の編集許可を区別|
|編集場所|**追加提案**|専用の編集用コピーを修正し、「採用」で元フォルダへ反映|
|元に戻す|**追加提案**|未採用の編集単位を編集用コピー内で戻す。採用後は別の取消操作として扱う|
|プレビュー隔離|利用者合意・実装検証中|アプリ操作権限を持たない専用WebView＋読取り専用配信。HTTP(S)通信を許可。iframeの有無は実装方式で判断|

編集用コピーは、05の「自動修正後に確認」を具体化する案。**採用まで元ファイルが変わらない**という追加の操作仕様を伴う。元ファイルを直に修正する方式を望む場合は、§7の差分帰属・復元方式を再設計する。両方式を初期版に並立させない。

## 3. 画面と操作

```text
┌ Visual Editor ─ [HTMLを開く] [再読み込み] [選択／操作] ─┐
│ 左:既存一覧      │ 中央:Preview        │ 右:Codex Chat  │
│ プロジェクト     │ index.html          │ 対象チャット名 │
│ チャット         │ 編集用コピーを表示  │ 選択要素 3件   │
│ エージェント情報 │                     │ 関連ファイル   │
│ 対象ファイル一覧 │ 選択枠・親のパンくず│ 会話・承認     │
│                 │                     │ 簡易メニュー   │
│                 │                     │ 指示入力・送信 │
├ 状態:変更を確認 ─ 変更ファイル2件 ─ [採用] [再修正] [元に戻す] ┤
└──────────────────────────────────────────────────────┘
```

- HTMLを選ぶと、プロジェクトルート、関連ファイル候補、対象チャットを確認できる開始画面へ進む。既存のプロジェクトルートがあれば提案し、なければHTMLの親フォルダを提案する。Gitルートへの無条件拡大はしない。
- 左の対象ファイル一覧は既存一覧内の折りたたみ区画。全プロジェクト用Explorerの新実装を初期必須にしない。
- 右チャットは既存の会話・承認カード・送信状態・モデル表示・中断を保持。選択情報を会話上部にコンパクトに追加する。
- 現在右にあるドックは右ペインの「チャット／エージェント」タブへ移す。承認件数と状態はどちらのタブにも表示し、監視窓も従来どおり使える。通常モードの配置は維持。
- 幅が狭いときは左を折りたたみ、右は開閉可能とする。960pxでもプレビューと入力欄を操作できる。専用WebViewがメニューやダイアログを覆わないよう、表示領域を退避／非表示にする必要がある。
- 「選択モード」はクリックによるリンク・ボタン動作を抑止。「操作モード」はページ動作を優先して選択を変えない。切替で保存ファイルを書き換えない。
- 下書き、選択、表示HTML、チャットは編集セッション単位に保持。別チャット選択を送信先の暗黙変更にしない。
- 変更確認には見た目に加え、ファイル一覧・追加／変更／削除・ソース差分を置く。AIの完了文だけで検証成功と表示しない。

### 3.1 選択操作

|操作|動作|
|---|---|
|ホバー|最前面の対象要素を枠表示。ページへ書込みをしない|
|クリック|単一選択。選択要素がない場所では解除|
|Ctrl＋クリック|要素を集合へ追加／解除。追加した要素を主選択にする|
|親を選択|主選択を親へ置換。他の選択は保持し、重複を除去|
|親パンくず|主選択の祖先を直接選ぶ。`html`までを上限にする|
|Esc|プレビューにフォーカスがあるとき全解除。チャット入力中のEscを奪わない|

複数選択は順序と主選択を持つ。親子が同時に選ばれていればUIで示し、送信時に関係も添える。初期提案上限は50要素。超過時は理由を表示し、無言で切り捨てない。SVG要素は選択可能、canvasの内部図形・閉じたShadow DOM・子iframe内部は初期対象外と表示する。

## 4. 06: 編集対象ファイルの管理範囲（推奨案）

**「ルート内の関連ファイルを自動検出し、確認した集合を編集範囲にする」方式を推奨する。** HTMLだけではCSS分離ページを十分編集できず、プロジェクト全体への無制限な編集は復元・確認が曖昧になるため。

ファイル集合を次の3つに分ける。

|集合|用途|初期ルール|
|---|---|---|
|編集対象|AIの修正と採用に含める|選択HTML、ローカルCSS／JS／mjsの検出候補を開始時に確認。追加HTMLは利用者が追加|
|表示依存|プレビューの読取り用|画像・フォント等。既定でAIの編集／採用対象にしない|
|対象外|コピー・配信・採用を拒否|ルート外、秘密情報、実行ファイル、リンク、`.git`、認証・キャッシュ等|

HTMLの`link[href]`／`script[src]`／画像等、CSSの`@import`／`url()`、JSの静的`import`／文字列リテラルの動的`import()`を再帰走査する。循環を検出し、URLのquery・fragmentはファイル解決から分離する。インラインCSS／JSは元HTMLに属する。ネットワーク先は一覧表示のみで取得しない。

式から作る動的パス、`fetch()`のデータ、import map、CSSOM、実行時ローダーは静的解析だけで完全判定できない。「未解決依存」と示す。利用者はルート内のJSON等を表示依存へ追加できる。自動で全ディレクトリを公開しない。SCSS／TS／JSX、ビルド、npm導入、バックエンド起動は初期対象外。

`../`は正規化後にルート内なら解決可能。`/assets/...`は選択ルート基準に対応付ける。`<base>`はルート内のパスだけを対応付け、外部・ルート外なら警告して不許可。Windowsの大小文字、URLエンコード、UNC、ドライブ絶対パス、ADS、junction／symlink／reparse pointを検査し、最終実体が境界外なら拒否する。検査とopenの間の差替えも考慮する。

探索・コピーの件数／総バイト／単一ファイルには実装前に上限を定める。上限超過は不足ファイル付きで停止し、完全に表示できたと偽らない。秘密情報の除外は拡張子だけに頼らず、`.env*`、鍵・認証ファイル等を明示拒否する。対象選択が秘密情報を含めない保証にはならないため、コピーするファイル一覧を利用者が確認できるようにする。

新しいCSS／JSを作る場合は許可したディレクトリ・種別内に限る。AIの範囲拡大要求は右チャットへ表示し、利用者が範囲を追加した後に続ける。範囲外変更を観測したら採用を止める。

これはAgentDockが扱う編集・配信・採用の範囲。Codexのsandboxはファイル単位の許可リストと同一ではない。AIへのプロンプト指定だけを厳密なOS書込み制限と表示しない。

## 5. プレビュー方式と安全境界

### 5.1 推奨構成

```text
信頼するmain画面                    Rust Host
  会話・承認・採用 ──既存IPC────────→ 送信／差分／採用
  選択情報の表示 ←──正規化イベント───┐
                                     │限定した選択・読込イベントのみ
専用preview WebView（アプリ権限なし） │
  アプリ管理の薄い表示shell ──────────┘
    sandbox iframe（未信頼HTML＋選択スクリプト）
             ↓ GETのみ
  127.0.0.1の専用配信 → 公開用revision → 許可した表示ファイル
```

専用WebViewを中央の矩形へ配置する案を第一候補とする。既存のTauri/Cargo設定で可能な埋込みAPI、WebView2の資源要求・frame navigationの遮断、限定メッセージ橋、重なり順は**技術検証が必要**。別ウィンドウを開くだけで01の中央配置を満たしたとはしない。

iframeは`allow-scripts`だけを基本とし、`allow-same-origin`、フォーム送信、ポップアップ、ダウンロード、上位移動等を許可しない。親はiframe DOMを直接読まず、配信用HTMLに注入した選択スクリプトのメッセージを受ける。元HTMLは注入のために保存し直さない。

Tauriのcapabilityは窓とWebViewの両方の適用範囲を確認し、previewへ既存`main`権限が継承・合成されない構成にする。**独自Tauriコマンドも含めて呼出元を拒否する**。現在の`UserConfirmed`はコマンド呼出しの入口で作るため、プレビューから呼べるままでは安全ではない。Tauri APIのJS変数を隠すだけでは対策にならない。[Tauri公式のCapabilities](https://v2.tauri.app/security/capabilities/)を参照。

iframeのsandboxはWeb標準に基づくが、これだけをローカル権限・通信の完全な隔離とみなさない。[HTML Standardのiframe仕様](https://html.spec.whatwg.org/multipage/iframe-embed-object.html)を参照。

### 5.2 配信と通信の制限

- 内部配信は利用者指定の開発サーバーではない。Rust管理の読取り専用サーバーで、`127.0.0.1`の空きポートだけにbindする。セッションごとの推測困難なURLトークンと公開revisionで経路を分離する。
- 相対ディレクトリ構造を維持。各revisionは変更不能の公開用コピーとし、HTMLとCSSが異なる時点になることを避ける。`no-store`、適切なMIME、`nosniff`、`Referrer-Policy: no-referrer`を設定する。
- ディレクトリ一覧、任意パス引数、POST／書込みAPI、プロキシ、シェル、Tauri IPCを配信サーバーに設けない。許可ファイル台帳にない要求は拒否。トークンを通常ログに記載しない。
- opaque originからのmodule／font／許可済みローカルデータの読込みは限定的なCORS応答が必要になりうる。`Origin: null`を認証と扱わない。トークン付きの静的公開対象だけに適用し、credentialsを許可しない。
- HTTPヘッダーのCSPで資源・接続先を公開revisionへ制限し、`object-src 'none'`、`worker-src 'none'`等を設定する。iframeのPermissions Policyでもカメラ・マイク・位置情報等を拒否。
- HTTP(S)の外部資源・CDN・API・別loopbackへの通信は許可する。CSPやCDPによる完全通信遮断は行わない。`file:`・アプリ独自schemeやアプリIPC経由の任意ファイル操作は許可しない。表示対象を維持するためのtop遷移・別窓等の制御は、通信許可と分けて扱う。
- CDN/APIは通常のブラウザーの通信条件で利用できるようにする。CORS・認証・cookie・Service Worker等の互換性は別に確認し、完全互換は保証しない。preview profileをAgentDock本体の設定・認証と共有しない。

### 5.3 メッセージ境界

受信は`ready`、`hover`、`selectionChanged`、`loadError`等の固定schemaだけとする。shellは送信元window、session、revision、navigation世代、nonce、サイズ／頻度を検査する。opaque iframeの`origin`は`null`になりうるため、それだけで認証しない。navigationごとに接続を破棄して再生成する。

ページJSと選択スクリプトは同じページで動くため、nonceもDOM情報も悪意あるページから完全に保護できない。**選択データは常に未信頼入力**。セレクタやHTMLをコマンドとして実行しない。自動送信・承認・ファイル読み書き・範囲追加を要求できるメッセージ種別は設けない。mainの実際の利用者操作だけが送信・採用の起点になる。

## 6. DOMとソースの対応付け

配信時に位置情報対応のHTMLパーサーで元ソースを解析し、静的要素に一時node IDを付ける。IDとファイル／バイト範囲／行列／ソースhashの対応表はHost管理。変更されたファイルを以前の行番号で編集させない。

再シリアライズでHTML全体の書式を変える方式は避け、元ソース位置への最小注入を検討する。予約属性衝突、HTMLの暗黙要素（`tbody`等）、不正HTMLの補正、注入によるCSS・JS挙動への影響を検証する。対応が取れない要素に行番号を捏造しない。

選択情報:

|分類|内容|
|---|---|
|識別|session ID、公開revision、文書パス、node ID、主選択、選択順序|
|DOM|タグ、id、class、限定した属性、可視テキスト抜粋、親子関係|
|位置|viewport相対rect、scroll、viewport寸法、倍率|
|候補|ユニーク性確認済みCSSセレクタ、DOMパス、祖先の指紋|
|ソース|一致時のファイルと範囲、hash、対応状態（確定／候補／不明）|
|補助|必要なcomputed styleの抜粋、関連CSS／JS候補|

セレクタは一意性を確認し、IDの重複や特殊文字を処理する。セレクタは恒久IDではない。`input`の値、password、hidden属性の値、ページ全体のHTML、認証情報を自動で収集しない。テキスト・属性・要素ごとのHTML抜粋には長さ上限と省略表示を設ける。

JS生成要素は、静的祖先・テキスト・属性・関連script等を「調査の手掛かり」として送る。JSの生成元やCSSルールの由来はDOMだけでは一意に決められない。AIがソース調査する前提とし、「生成元未確定」を示す。node IDの複製や属性変更もありうるため、対応表との照合なしに確定扱いしない。

### 6.1 更新後の選択

公開revisionが変われば旧選択をいったん無効化。同じ静的ソース位置、ユニークなid、構造・テキストの指紋で候補を探す。新revision内で一意かつ整合した場合だけ復元し、曖昧なら「要素が変わったため再選択」と表示する。`nth-child`が同じという理由だけで別要素を選ばない。

復元件数を表示し、送信時は現在のrevisionとファイルhashを再確認する。古い画面からの送信は再読み込み／再選択を求める。ページのスクロールは可能なら維持し、ページ内部のJS状態や入力値の復元は初期保証外。

## 7. 編集用コピー・差分・採用・復元

### 7.1 編集セッションと編集単位

1つの編集セッションが元ルート、HTML、許可範囲、専用コピー、1つの通常チャットを持つ。Gitの有無を問わず利用でき、`git init`・自動コミットをしない。

開始時に許可範囲の現在のファイル内容をバイト単位で控えてコピーする。HEADではなく、**利用者の未コミット変更を含む現在内容**を基準にする。ルート外の`~/.codex`、アプリ設定・認証はコピーしない。プロジェクト内の適用対象`AGENTS.md`は編集対象外の指示資料として扱い、上位から適用される指示の扱いも開始前に確認する。元ルートをAIの追加書込みrootにしない。

「今回」は、1回の編集送信から停止照合・変更収集までの編集単位（transaction）。再修正は次のtransactionとして同じコピーへ積み重ねる。実行中steerは同じtransactionに属する。初期版はVisual編集の完了後自動送信キューを無効とし、次の依頼は入力欄へ保持する。既存の通常チャットキューは変更しない。

各transactionについてB（直前）とE（停止確認後）を保持。ファイル監視やAIの`fileChange`だけに頼らず、許可範囲の全ファイル状態を照合し、シェル経由編集も検出する。表示依存や範囲外に変更があれば要確認として採用を止める。

### 7.2 3つの操作

|操作|挙動|
|---|---|
|採用|前回採用基準から現在コピーまでの累積差分を元へ反映。複数回の再修正を含めて確認。成功後に基準を更新|
|再修正|現在結果を残したまま次のtransactionを開始。新しいBを控えてから送信|
|元に戻す|最新の未採用transactionのE→Bをコピー内で復元。元フォルダは変更しない。戻す対象の指示とファイル数を明示|

一括で初期状態へ戻す操作は別途明示する。初期MVPの主操作は最新transactionのみ。採用済み変更に通常の「元に戻す」を適用しない。採用後の取消を追加する場合は元ファイルの競合照合と別の利用者操作を必要とする。

### 7.3 採用の安全条件

採用は新設するパッチ反映処理。既存のGitコミット取り込みと区別する。

1. 親・観測子孫の終端、子孫走査の完全性、送信受理不明なし、未確定操作なしを既存の証拠で確認する。親の「終わりました」だけでは通さない。実行中外部プロセス等によりコピーの静止が確認できなければ保留。
2. 元ルートとコピーをフォルダ操作ガードで確保。重複するチャットのcwd・追加root、停止未確認、取り込み・戻す操作も検査する。
3. 許可範囲、最終実体パス、ファイル種別、採用対象のhash、元ルートの同一性を再確認する。Git対象ならHEAD／ブランチ変更・Git操作中も保留。差分には新規と削除も含む。renameは初期版では追加＋削除扱い。
4. 元ファイルCと前回採用基準Oが一致する場合だけ通常反映する。元に他作業の変更があれば、**重ならないように見えても初期版では自動mergeせず保留**。コピーと元の両方を残し、差分を提示する。新規は「元に存在しない」、削除は「元がOと同じ」を条件にする。
5. 計画IDに対象・期待hash・session世代を固定。確認後に変化した計画は失効。AIが差分を説明したことを反映許可と代用しない。
6. 書込み前の元内容と反映予定を控え、操作台帳を永続化する。現在のWindows実装案は、対象と祖先を検証し、変更ファイルを共有拒否ハンドルで保持したまま書き込み、直後に照合する。ハードリンクは拒否する。一時ファイル置換とは異なり、単一ファイルでも途中終了で部分内容が残り得る。すべて確認できて初めて成功記録を残す。

複数ファイルの反映は一括atomicではない。途中失敗・異常終了では`partial`／`unknown`としてファイル別に記録し、再送・採用ボタンの再利用を止める。再起動後は台帳と現物を読取り照合し、未処理／反映済み／競合を示す。自動で残りを反映したり、外部変更を戻したりしない。

AgentDock内の操作ガードは外部エディタや外部プロセスを完全には排他できない。厳密に他作業を保護するには、Windows上で書込み共有を拒否するハンドル等による競合防止と置換手順の成立を検証する必要がある。**hash確認だけで検査後の競合がなくなったとは言わない**。成立しないときは安全な反映を保留し、差分の手動取り込みを案内する。

### 7.4 コピー内の復元

現在CがEと一致する対象だけBへ復元。コピーに手編集や別の更新が入っていれば上書きせず保留する。復元前のCも控え、複数ファイルの部分成功を記録する。Git reset／checkoutや元フォルダ全体のバックアップ上書きで代用しない。

削除ファイルの復元、新規ファイルの削除も停止確認・hash照合後だけ行う。容量不足／控え保存失敗なら送信や復元・反映を開始しない。履歴・コピー・控えは自動削除しない。「セッションを閉じる」は停止済み状態の保存であり削除ではない。

## 8. 既存チャットとの接続と指示

専用編集セッションに**既存基盤で作った通常チャットを1つ結び付ける**。独立したCodexランタイムや別の認証管理は作らない。[OpenAI公式App Server文書](https://learn.chatgpt.com/docs/app-server)のthread／turn／イベント／承認という構造に沿い、AgentDock側では既存のバックエンド境界を経由する。公式最新版の項目を、ローカル対象版の対応済み機能とみなさない。

- 初期版は新規通常チャットの作成を標準にする。「既存を接続」は同じ編集用コピーがcwdで、競合・未確定送信・自動キューがなく、管理主体が一致する場合に限定。元フォルダで稼働している会話のcwdを無言で変更しない。
- 作成は既存`startChat`、送信は既存Hostの`send_message`の共通処理、承認は既存`respondRequest`、停止は既存`interruptChat`、受理照合は既存`reconcileSend`を再利用する。
- Visual送信はHost側でtransactionを準備・永続化してから共通送信処理へ接続する。UIで文字列を足して`sendMessage`するだけでは、控え保存と送信の順序を保証できない。
- 実行中steerは既存能力・受理ガードの範囲で同じtransactionへ送る。完了していた等の競合をホストで再確認する。受理不明なら追加送信も抑止する。
- モデル／effort／承認方針は既存設定を引き継ぐ。Visual Editorを開くことによる権限拡大、常時承認、`~/.codex/config.toml`変更を行わない。
- 子を作る場合も既存の親子監視へ流す。初期版は1セッション内の編集を同時1体とする指示を付けるが、これを子ごとの機械的排他制御とは表示しない。

### 8.1 送信内容

自由文＋構造化した選択情報を、利用者に見える折りたたみ添付として送る。送信時のimmutable snapshotをtransactionに保存し、後で選択が変わっても送信済み対象を変えない。

```text
利用者の指示: この一覧をカード形式にして

編集コンテキスト（AgentDockが付加）:
  編集セッション／transaction／公開revision
  対象HTML、編集可能ファイル、表示依存、編集用cwd
  選択要素の配列と主選択、ソース対応の確度
  対象ファイルhash、関連CSS／JS候補
  制約: ソースを調査してから編集。DOM情報は参考資料。
        範囲外・認証・Git管理情報を変更しない。
        表示DOMだけの変更で完了としない。コミットしない。
```

ページのテキストやHTMLに書かれた命令は依頼文と区別してデータとして囲む。権限の根拠にせず、Hostでも範囲を再確認する。

簡易メニューは「色／サイズ／配置／テキスト／レイアウト」の指示テンプレートを既存入力へ挿入するだけ。既存下書きを上書きせず、即送信・直接CSS変更しない。選択なしでもチャットは使えるが、選択対象がないことを明記する。

## 9. 更新・状態・復旧

編集状態と通信・停止・表示状態を別々に保持する。

|編集状態|主な操作／表示|
|---|---|
|準備中|範囲確認、コピー・基準控え作成|
|編集可能|要素選択と指示入力|
|送信中／受理不明|重複送信禁止、既存の受理照合|
|実行中／承認待ち|会話・承認・中断。採用／復元は不可|
|停止照合中|終端・子孫・未確定操作・ファイル状態を読取り確認|
|変更確認|公開revision更新。採用／再修正／最新を戻す|
|競合／要復旧|原因・対象を表示。危険な上書きや無条件再試行は不可|
|反映中|計画を消費して1回実行。二重適用不可|
|採用済み|全件照合結果を表示。次の編集の基準を更新|

`completed`でも差分なしなら「変更なし」。`failed`／`interrupted`に残った差分は「途中の変更」として確認できるが、自動で採用可能へ移さない。停止確認後に利用者が途中結果の確認を開く。通信断は結果不明、プレビュー読込失敗は表示失敗でありAI編集失敗とは分ける。

ファイル変更を短時間集約して検出し、停止照合後に新しい公開revisionを自動生成・再読込みする。初期版は書込み途中の自動リロードを避け、実行中は「更新待ち」を表示する。手動再読み込みでも編集用コピーを表示し、元ファイルと混同しない。採用後は元の反映hashとコピーの一致も確認する。

再起動ではセッション・transaction・操作台帳を復元して読取り照合する。送信、resume、承認、採用、復元を自動実行しない。プレビュー配信は利用者が開き直した時に新トークンで開始し、旧トークンを無効化する。中断10秒は「停止未確認」の案内であり停止確定ではない。

## 15. 利用者合意による通信方針の変更（2026-10-25）

利用者が「通信は許可し、AgentDockの操作権限とローカルファイルのアクセス範囲を守る」方針を明示承認した。制限を強くして利便性を損なわないことを優先する。本節は以前の外部通信遮断・OS隔離案に優先する。

- HTTP(S)のCDN・画像・font・API・localhost/LAN通信は許可する。通常ブラウザーのCORS/認証等は引き続き適用される。
- プレビューにAgentDockの独自command・承認・任意ファイル操作を許可しない。capabilityをmain windowに一致させるだけでchild WebViewが保護されるとは仮定せず、WebView単位の権限と共通commandガードを確認する。
- 公開するローカル資源は利用者が選んだroot内の表示用ファイルに限定し、秘密設定・実行ファイル・範囲外・junction等を配信しない。配信とAIの編集許可は別管理。
- 過去のTCP到達試験は旧方針の測定記録として保持する。TCP接続があったこと自体を、現行要件の失敗や情報漏えいの証明としない。OS通信隔離の実装は初期版対象から外す。
- 最初の統合は読取りプレビューと要素選択、既存チャット入力欄への情報挿入まで。情報挿入は送信・自動編集・採用ではない。V2/V3のtransaction・専用コピー・差分/復元・安全な採用は別途実装し、未実装の操作を成功表示しない。
