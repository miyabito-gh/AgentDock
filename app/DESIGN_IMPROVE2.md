### C.2 記法（[S1] で確認）

- 先頭のコロンは **1〜3個**（`:name{…}`・`::name{…}`・`:::name{…}`）。名前は英数字・`_`・`-`、先頭は英字。
- 属性 `{key=value …}`: 値は `"…"`・`'…'`（改行不可）か、引用符なし（空白か `}` まで）。キーの重複は無効。
- `[label]` は `codex-followup` だけが持てる。
- 引用符内のエスケープ: git 系は**文字どおり**（`cwd="C:\repo\"` の `\` を保つ）、code-comment は `\"` を引用符として扱う。
- 走査量に上限（入力長の定数倍）を設け、壊れた候補の繰返しで固まらないようにしている。
- 表示時はコードスパン・コードブロック・リンク・HTML の中は対象外（[S3]。git 系の行単位の除去 [S2] はこの区別をしていない）。

| `::automation-update{…}` | 不明 | 上記リポジトリには**見当たらない** | **未確認**（デスクトップアプリ固有とみられるが根拠なし） |

補足（未確認）: これらの指示をモデルに教える指示文は上記リポジトリに無い。デスクトップアプリ側から与えている可能性があるが確認できていない。AgentDock（App Server 経由）でどの程度出るかも未確認（`~/.codex` を共有するため、デスクトップアプリで作った会話の履歴には含まれうる）。

### C.4 AgentDock での扱い（提案）

| 指示 | 提案する表示 | 操作（すべて押した時だけ） | 処理しないこと（理由） |
|---|---|---|---|
| git-stage | 小さな記録チップ「Codex の報告: 変更をステージ（cwd 名）」 | 「変更を確認」→ 既存の変更確認画面（`changes` ダイアログ、読取り） | ステージの実行・取消（書込み。報告が事実かも分からない） |

| git-create-branch | 記録チップ「Codex の報告: ブランチ作成 `branch`」 | なし。必要なら既存の `gitInfo`（読取り）でヘッダーのブランチ表示を更新（TUI と同じ考え方、自動の読取りは1回だけ） | ブランチの作成・切替 |

| git-create-pr | 記録チップ「Codex の報告: PR 作成 `branch`（下書き）」 | `url` が http・https なら既存のリンク確認を経て開く | PR 作成（外部への書込み） |

| 壊れた指示 | 原文のまま | なし | 隠すと情報を失う（TUI は git 系の壊れたものを隠すが、AgentDock は見せる側に倒す） |

安全条件（全指示）:
1. 指示を読んだだけでは何も実行しない。書込み（git 操作・ファイル変更・送信）は一切しない。任意コマンドを実行しない。承認・質問への回答の代わりにしない。
2. `cwd`・`file`・`path` が、そのチャットの作業フォルダ（追加フォルダ・worktree を含む）の内側と確認できない時は、ボタンを出さず「作業フォルダ外」とだけ示す。UNC 等のネットワークの場所は自動で触れない（既存 `pathCandidate` の規則）。
3. 「Codex の報告」と明記し、実際にその状態であるとは表示しない（未確認の操作を成功表示しない）。
4. URL は http・https だけ、既存のリンク確認を通す。
5. コードスパン・コードブロック・リンク・生 HTML の中は変換しない（既存 `remarkRefs` の `SKIP` と同じ）。依頼（ユーザーの発言）は整形しない（M16 の決定）。
6. 属性の長さに上限（例: 値1つ 4,000 文字、指示1つ 8,000 文字）、走査量に上限（[S1] と同じ考え方）。超えたら原文のまま。
7. 逐次表示中は、閉じていない指示は原文のまま出し、閉じた時点で変換する（コードブロックと同じ扱い）。
8. コピー・Markdown エクスポート・会話内検索の対象は**原文**（今と同じ。変換は表示だけ）。検索は表示文字にも当たるよう、チップの文言も検索対象にする。
