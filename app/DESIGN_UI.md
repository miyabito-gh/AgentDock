## 2. 共通の規則（どの案でも同じ）

### 2.1 色の意味の割り当て（1色1意味）

| 意味 | 使う色 | 使ってよい場所 |
|---|---|---|
| アクセント（主操作・選択中） | `--accent` | 主ボタン・選択行の縦棒・選択中のタブ・フォーカス周辺 |
| 実行中・初期化中 | `--run`（青） | 状態のみ |
| **要対応**（対応待ち＝承認・質問、要確認） | `--wait-*`（黄） | 状態・一覧の印・ファイルの「要確認」・警告帯。**それ以外に黄を使わない** |
| 失敗・危険操作 | `--fail-*`（赤） | 状態・失敗の印・危険の確認・エラー帯 |
| 中断 | `--int`（紫） | 状態のみ |
| 完了・終了 | `--done`（A・B は緑、C は無彩色） | 状態・「戻し済み」 |
| 待機（idle）・状態不明 | 無彩色 | 状態のみ（不明は破線） |
| 鮮度の注意（履歴のみ・要照合） | `--stale`（茶） | 鮮度表示の文字だけ（面は塗らない） |
| 確認状況「未確認」 | 無彩色の破線枠 | 操作名の直後・ダイアログ冒頭 |
| 会話内検索の一致（v0.3） | `--find-hit`（アクセントの淡色）・`--find-cur`（アクセントの濃い面） | 検索のハイライトだけ（黄は使わない。`DESIGN_P5.md` §4） |

### 2.2 状態・鮮度・確認状況の見た目の文法

- **状態チップ**（§4.1）: 形＋文字＋色。実行中＝●、対応待ち＝◆、失敗＝■、中断＝縦2本、完了・終了＝✓、待機＝○、状態不明＝破線の○＋破線枠。「履歴で〜を確認」は同じ色の**破線枠・塗りなし**（live確認と区別）。一覧・中央ヘッダー・ドック・監視窓で同じ部品 `.st` を使う。
- **鮮度**（§4.2）: 塗りなし・控えめの文字色＋小さな印。受信中＝実線の輪に点、履歴のみ・要照合＝茶色の破線の輪、切断・非対応＝赤の斜線の輪。状態チップの隣に置くときは縦線で区切る。
- **確認状況「未確認」**の規則:
  1. 操作単位では、操作名の直後に文字「未確認」を常に出す（ボタン・メニュー・Ctrl+K・設定の各所）。見た目は**無彩色・破線枠・塗りなし・11px**。黄は使わない。
  2. ダイアログの中では冒頭に1回だけ（「未確認」＋説明1文）。同じダイアログ内で繰り返さない。
  3. 隠さない: 狭い画面・ホバー前・折りたたみでも消さない。文字を省いて記号だけにしない。
  4. 受理の表示（「受理済み: …」「未受理。次のターンから適用」）は本文色の文字で出し、緑や✓を付けない。
- **帯（バナー）**: 1つの原因につき1本。同じ原因を「説明文」と「非対応理由」で二重に出さない（P7）。警告＝黄、エラー＝赤、情報＝アクセントの薄い面。

### 2.3 窓まわり

- アプリ内の疑似タイトルバー（`TitleBar`）を主画面から外し、Windows標準のタイトルバーだけにする（2026-10-10 決定）。接続先切替（`modeMenu`）の版タグ「Codex 0.160.0」はメニューバー右端へ移す（押すと今と同じ `modeMenu`）。OSの×は今どおりトレイ格納。アプリ内の最小化・最大化（`noop`）は消える。アプリ内の模擬監視窓（`MiniWindow`、モック用）は `TitleBar` を使い続けてよい。
- 小さなポップオーバー（ヘッダーの「…」、鮮度の説明、入力欄の「⋯」、ドックの「表示」）は1つの部品 `Popover`（`ui/Popover.tsx`）で作る。開くボタンは `aria-expanded`、中は `role="menu"`（操作の並び）か `role="dialog"`（説明と選択欄）。Esc・外側クリックで閉じ、閉じたら開いたボタンへフォーカスを戻す。見た目は `.dropdown` と同じ面・線・影。
- 「?」アイコン（`.help`）: 説明文を移した先。`<button aria-label="説明">?</button>` に `title`（ホバー）と、押したときの小さな `Popover`（キーボードで読める）。説明の文言はそのまま入れる。

### 2.4 ダイアログの構造

- ヘッダー（題名＋×）／本文（スクロール）／フッター（左＝副操作、右＝「閉じる（またはキャンセル）」＋主操作。主操作がいちばん右で塗り）。
- 主操作が無効のときは、塗らずに灰色の無効表示（押せそうに見せない）。
- 危険な確定（2段目）は、対象の近くに赤い枠の確認ブロックを出し、その中に「危険ボタン（塗り）」と「やめる」を置く。フッターの主操作とは分ける。
- 長い説明は「この操作について」の淡い面にまとめる（文言はそのまま）。

## 3. デザイン（採用: 案A＋すっきり化）

2026-10-10 ユーザー決定: 案Aを土台に、現行の方向性は保ったまま「もっとすっきり・わかりやすく」。疑似タイトルバーは外す。ドックのカードは情報を残して詰める。会話テキストの表示量を最大化する（§4）。

トークンの値の正本はモックのCSS（`gen-mocks.mjs` の `V.a.css`、`[data-theme=light]`・`[data-theme=dark]`）。実装では同じ値を `:root` と `@media (prefers-color-scheme: dark){:root{…}}` に移す。

案Aからの調整（本書が優先）:
- 完了の色は案Aどおり緑（`--done`）。ただし「✓＋文字」の形を必ず付け、面は塗らない（成功の強調に見せない）。
- 会話ヘッダーは1行（§4.3）。モックの2行ヘッダーは採らない。
- ヘッダーの操作は枠付きボタン群ではなく「…」メニューへ（§4.2 H11）。
- 入力欄は1行目だけに操作を置き、下の注記行（`.hint`）は問題があるときだけ（§4.3）。
- 左一覧・ドックの幅はドラッグで変える。既定幅は左240px・ドック320px（§5）。

- 一時パネル（960〜1279pxのドック、960px未満の左右）は今どおり固定幅 `min(300px,86vw)`。ハンドルも出さない。閉じているペイン（`l-off`／`r-off`）のハンドルも出さない。
- 中央の最小幅は480px。ドラッグ・キー操作では中央が480px未満になる幅にしない。窓を狭めたときは保存値を変えずに表示幅だけ縮める（表示幅＝`min(保存値, 窓幅 − もう一方の表示幅 − 480)`、ただし最小幅は下回らない）。窓を戻せば保存値に戻る。この計算は純粋関数 `ui/paneWidth.ts` に置き、単体テストを書く。
- 表示: 境界線の位置に幅6pxの当たり判定（見た目は今の1px線、ホバー・フォーカス・ドラッグ中は2pxのアクセント色）。カーソル `col-resize`。
- ドラッグ: Pointer Events＋`setPointerCapture`。動かしている間は `.body` の CSS変数 `--lw`／`--rw` を `requestAnimationFrame` で直接更新し、Reactの状態更新・保存はしない。ドラッグ中は `.body.resizing` を付けて文字選択を止め、カーソルを全体で `col-resize` に、遷移アニメーションを止める。Escでドラッグ前の幅に戻す。指を離したときに1回だけ保存する。
- キーボード: ハンドルは `role="separator"`、`aria-orientation="vertical"`、`aria-label="チャット一覧の幅"`／`"ドックの幅"`、`aria-controls`、`aria-valuemin/max/now`（px）、`tabIndex=0`。←→で8px、Shift＋←→で32px、Homeで最小、Endで最大、Enterで既定。キー操作の保存は最後の操作から500ms後に1回。ドックのハンドルは←で広がる（向きは見た目どおり）。
- ダブルクリック（またはEnter）で既定幅に戻し、保存値は「未設定」に戻す。
- 保存場所: アプリ設定（`AppSettings`、`settings.json`）に `layout: { leftWidth: number | null, dockWidth: number | null }` を `#[serde(default)]` で追加（null＝既定）。既存の `setAppSettings` で保存する（他の設定と同じ経路・保存状態・容量確認）。保存に失敗したら既存の書き方でトースト「パネルの幅を保存できませんでした」を1回出し、表示幅はそのまま。読み込んだ値は最小・最大で丸めてから使う。窓の位置・サイズ（`windows.json`）とは別。
- 監視窓・モック用 `MiniWindow` には付けない。
