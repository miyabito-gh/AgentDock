# DESIGN_UI — 段階④-UI 見た目の改善（設計）

版 0.1（2026-10-10）。対象: `app/src/styles.css` と `app/src/ui/*.tsx`・`App.tsx` の**見た目だけ**。
比較モック: `app/design/mock-a.html`・`mock-b.html`・`mock-c.html`（生成元 `app/design/gen-mocks.mjs`。`node app/design/gen-mocks.mjs` で再生成）。

## 0. 守ること（全タスク共通）

- 挙動・文言の意味・状態の根拠表示は変えない。「未確認」「live未確認」「受理済み／未受理」「履歴で〜を確認」「状態不明」を、成功・完了に見せない。消しもしない。
- 状態（§4.1）と鮮度（§4.2）は別の見た目で出す（§2.2）。片方からもう片方を推測できる見た目にしない。
- 色だけで区別しない（形＋文字＋色）。文字のコントラストはWCAG AA（本文4.5:1、大きい文字・部品の線3:1）。
- キーボード操作とフォーカス表示を保つ。通知・更新でフォーカスを動かさない。
- D07: 1280px以上は3領域、960〜1279pxはドックを一時パネル、960px未満は左右とも一時パネル（境界は今と同じ）。
- ダークモードはOS設定に従う（`prefers-color-scheme`）。アプリ内の切替は作らない。
- ライブラリ・Webフォントは追加しない。Windows標準のフォントだけ使う。

## 2. 共通の規則（どの案でも同じ）

### 2.1 色の意味の割り当て（1色1意味）

| 意味 | 使う色 | 使ってよい場所 |
|---|---|---|
| アクセント（主操作・選択中） | `--accent` | 主ボタン・選択行の縦棒・選択中のタブ・フォーカス周辺 |
| 実行中・初期化中 | `--run`（青） | 状態のみ |
| **要対応**（対応待ち＝承認・質問、要確認） | `--wait-*`（黄） | 状態・一覧の印・ファイルの「要確認」・警告帯。**それ以外に黄を使わない** |
| 失敗・危険操作 | `--fail-*`（赤） | 状態・失敗の印・危険の確認・エラー帯 |
| 中断 | `--int`（紫） | 状態のみ |
| 完了・終了 | `--done`（A・B は緑、C は無彩色） | 状態・「戻し済み」 |
| 待機（idle）・状態不明 | 無彩色 | 状態のみ（不明は破線） |
| 鮮度の注意（履歴のみ・要照合） | `--stale`（茶） | 鮮度表示の文字だけ（面は塗らない） |
| 確認状況「未確認」 | 無彩色の破線枠 | 操作名の直後・ダイアログ冒頭 |

### 2.2 状態・鮮度・確認状況の見た目の文法

- **状態チップ**（§4.1）: 形＋文字＋色。実行中＝●、対応待ち＝◆、失敗＝■、中断＝縦2本、完了・終了＝✓、待機＝○、状態不明＝破線の○＋破線枠。「履歴で〜を確認」は同じ色の**破線枠・塗りなし**（live確認と区別）。一覧・中央ヘッダー・ドック・監視窓で同じ部品 `.st` を使う。
- **鮮度**（§4.2）: 塗りなし・控えめの文字色＋小さな印。受信中＝実線の輪に点、履歴のみ・要照合＝茶色の破線の輪、切断・非対応＝赤の斜線の輪。状態チップの隣に置くときは縦線で区切る。
- **確認状況「未確認」**の規則:
  1. 操作単位では、操作名の直後に文字「未確認」を常に出す（ボタン・メニュー・Ctrl+K・設定の各所）。見た目は**無彩色・破線枠・塗りなし・11px**。黄は使わない。
  2. ダイアログの中では冒頭に1回だけ（「未確認」＋説明1文）。同じダイアログ内で繰り返さない。
  3. 隠さない: 狭い画面・ホバー前・折りたたみでも消さない。文字を省いて記号だけにしない。
  4. 受理の表示（「受理済み: …」「未受理。次のターンから適用」）は本文色の文字で出し、緑や✓を付けない。
- **帯（バナー）**: 1つの原因につき1本。同じ原因を「説明文」と「非対応理由」で二重に出さない（P7）。警告＝黄、エラー＝赤、情報＝アクセントの薄い面。

### 2.3 窓まわり

- アプリ内の疑似タイトルバー（`TitleBar`）を主画面から外し、Windows標準のタイトルバーだけにする（要確認: 質問2）。接続先切替（`modeMenu`）の「Codex 0.160.0」はメニューバー右端へ移す。OSの×は今どおりトレイ格納。アプリ内の模擬監視窓（`MiniWindow`、モック用）は `TitleBar` を使い続けてよい。

### 2.4 ダイアログの構造

- ヘッダー（題名＋×）／本文（スクロール）／フッター（左＝副操作、右＝「閉じる（またはキャンセル）」＋主操作。主操作がいちばん右で塗り）。
- 主操作が無効のときは、塗らずに灰色の無効表示（押せそうに見せない）。
- 危険な確定（2段目）は、対象の近くに赤い枠の確認ブロックを出し、その中に「危険ボタン（塗り）」と「やめる」を置く。フッターの主操作とは分ける。
- 長い説明は「この操作について」の淡い面にまとめる（文言はそのまま）。

### 2.5 部品の対応（実装時の置き換え）

| `.st`（ドック）＋一覧の無色の状態文字＋中央ヘッダーの状態文字 | 共通の状態チップ `.st`（§2.2）。一覧では面なし（文字＋印） |

## 3. デザイン案

トークンの値の正本はモックのCSS（`gen-mocks.mjs` の `V.a/b/c.css`、`[data-theme=light]`・`[data-theme=dark]`）。実装では同じ値を `:root` と `@media (prefers-color-scheme: dark){:root{…}}` に移す。

### 案A「業務ツール・高密度」（Windows 11 標準寄り）— **推奨**

- トーン: Windows 11 の設定アプリに近い、明るい灰色の面と白いカード。情報量は多いが整然。
- 文字: `"Segoe UI Variable Text","Segoe UI","Yu Gothic UI","Meiryo UI"`（英数字はSegoe、日本語はYu Gothic UI）。本文13px／小12px／最小11px、行間1.55（会話本文1.7）。等幅 `Cascadia Mono`。
- 余白: 4・8・14・16px。角丸4／6／8px。影は最小限（ダイアログのみ）。操作高さ28px。
- 配色（主要）: ライト 背景`#F3F3F3` 面`#FFFFFF` 文字`#1B1B1B/#545454/#686868` 線`#E3E3E3/#C2C2C2` アクセント`#005FB8`。ダーク 背景`#202020` 面`#2B2B2B` 文字`#F2F2F2/#C9C9C9/#A8A8A8` アクセント`#4CC2FF`（文字は濃紺`#00243A`）。

- 部品: ヘッダー操作は枠付きの連結ボタン群。状態は薄い面のチップ。ドックのカードは左3pxの状態色、承認待ち・失敗は面も色付け。設定は左に縦の分類。
- 密度: ドックのカード約4行（約95px、現行比−25%）。左一覧1行44px。
- 長所: Windowsらしい。情報量を保ったまま整理。監視用途（多数のカード）に向く。短所: 少し事務的。Yu Gothic UI は小さい字でやや細い。

### 案B「読みやすさ重視・ゆとり」（現行の紺緑を継承）

- トーン: 現行の配色（紺緑`#1E4D6B`）を残し、余白と行間を広げた柔らかい見た目。
- 文字: `"BIZ UDPGothic","Meiryo"`。本文14px／小12.5px／最小11.5px、行間1.7（会話本文1.85）。

### 案C「ミニマル・アクセント最小」（色は状態だけ）

- トーン: 白と墨の無彩色。主ボタンも墨色。色は状態の文字と、要対応（承認待ち・失敗）の面だけ。
- 文字: `"Segoe UI Variable Text","Segoe UI","Meiryo UI"`。本文13px、行間1.6。

- 長所: 状態の色が最も目立つ（色＝何か起きている）。静か。短所: 押せる場所が分かりにくい（枠なし）。完了が無彩色なので「完了」と「待機」の差は形と文字だけ。

## 5. ユーザーへの質問（選択式・最大3問）

1. **どの案にするか**（必須）
   - A 業務ツール・高密度（推奨）: Windows 11らしく、ドックに多くのカードが入る。少し事務的。
   - B 読みやすさ重視: 文字が大きく疲れにくい・現行に近い。見える数が減り、1280px付近で窮屈。
   - C ミニマル: 状態の色が最も目立ち静か。押せる場所が分かりにくい、完了が無彩色。
   - （部分の組合せも可。例:「Aの配色＋Bの文字サイズ」）
2. **アプリ内の疑似タイトルバー**
   - 外してWindows標準のタイトルバーだけにする（推奨）: 二重がなくなり、スナップ等もOS標準。版タグはメニューバー右へ。
   - 枠なし窓にしてアプリ内タイトルバーを本物にする: 見た目の統一感は高いが、ドラッグ・スナップ・最大化の実装と実機確認が増える。
   - 今のまま。
3. **ドックのカードの詳しさ**
   - 標準（推奨）: 名前・状態／パス／役割・担当／活動／時刻・根拠 の4〜5行を詰めて表示（現行の情報はすべて残す）。
   - 2段階: 既定は名前・状態・活動・時刻の2〜3行、カードを開くと役割・担当・パス・根拠。省スペースだが、役割・担当（§3.5 M05）が一目で見えなくなる。

## 6. 要判断（設計で決めず残したもの）

- 「完了」の色: A・Bは緑系、Cは無彩色。緑が「成功」に見える懸念がある場合はCの扱いを採る（質問1の回答で決まる）。
- ドック下端の注記（P15）の扱い: 文言を残す前提で、常設の2行を1行の小さい字にするか、見出しの補足（`title`）へ移すか。後者は常時見えなくなるため、決めるまでは常設のまま。
- ヘッダーの「未確認」の数は確認状況の表（`codex/parity_table.rs`）で決まる（スクリーンショット時点では差分・戻すが未確認）。表の更新は見た目の作業ではないため本書の対象外。
