## A. 組織実行（最優先）

### A1. Worker が実際に変更を書いてコミットするか（確認 #1）
1. 「新しいチャット」→ 作業フォルダに `C:\Users\wmasa\Documents\tmp\agentdock-trial` を指定する。
2. 組織実行の開始（「組織実行を開始…」またはチャットの「…」メニュー）→ テンプレートは **quality-loop**。依頼文の例: 「calc.py に、引き算 sub(a, b) を追加してください。README.md に1行説明も足してください。」
3. 依頼整理の会話が出たら、制約の言葉（「この段階では変更しない」など）が**確定依頼に入っていない**ことを確認して開始する。
4. 期待: plan → build → verify と進み、build の Worker が `calc.py` と `README.md` を変更してコミットする。
5. 控える: ① build が「要対応」で止まったか ② 止まった理由の文言 ③ 成果物パネルに変更ファイルが出たか。
   - 止まって「Worker が変更を書きませんでした」と出たら、報告の要旨を控える（どう答えたか）。

### A2. 並列で動くか（確認 #2）
1. 同じリポジトリで、テンプレート **standard**（計画して実行）を選ぶ。依頼: 「calc.py に mul と div、README に使い方、tests/test_calc.py に簡単なテストを、それぞれ独立に作ってください。」
2. 期待: Planner が複数のタスクに分け、**Worker が同時に2つ**動く（組織画面の「いまの動き」に2行）。
3. 控える: 同時に動いた Worker の数、worktree が分かれているか（`%LOCALAPPDATA%\com.agentdock.app\worktrees\` を見る）。

### A3. 読み取り専用の Reviewer がテストを実行できるか（確認 #3）
1. A2 のレビュー段階（Reviewer が動く）で、Reviewer の出力（「チャットを見る」）を開く。
2. 控える: Reviewer が `pytest` やテストコマンドを**実行しようとしたか／できたか／拒否されたか**。承認要求が出たか。

### A4. 差し戻し・再送の操作（確認 #4）
1. 差し戻し上限に当たった、または止まったタスクで、タスク表の操作を見る。
2. 期待: 「新しい試行で再送…」が出る（利用上限停止、turn 失敗、変更なしで止まったとき）。「失敗として確定」「取り消す」「手動に切り替え」も出る。
3. 実際に1回「新しい試行で再送…」を押して、追加指示を添えて送れるか、再送回数（試行 n/3）が増えるかを控える。

### A5. 承認待ちに答えて先へ進めるか（確認 #5）
1. Worker に、承認が要る操作をさせる（例: 依頼に「ネットワークにアクセスして…」ではなく、`git` 以外のコマンドの実行、あるいは作業フォルダ外への書き込みを要求する）。
2. 承認カードが出たら、組織画面の帯「Codex の承認・質問の待ちが N 件」→「要求へ」→ 役割チャットのカードで**答える**。
3. 期待: 答えるとタスクが進む。
4. 控える: 答えたあと進んだか／無反応か。無反応なら、AgentDock を再起動していたか、カードを押したときの表示（「取得不能」など）。

## C. 継続チャット（台帳と下書き支援）

### C1. K4: Codex が台帳を読めるか
1. 一般チャットを作り、目的メモに「議事録の様式を、決定事項→議題→次回までの宿題の順で書く」と書く。
2. 5往復ほど会話する（各往復に固有の情報を入れる。例: 1「議題は A 社の見積もり、金額は 1,234,567 円」、2「担当は山田さん」、3「期限は 11 月 15 日」…）。
3. 「…」メニューから引き継ぎを手動で開き、「資料を見る」で次を確認する。
   - 目次（往復番号と依頼の先頭1行）が出るか。台帳の予定パスが出るか。
4. 「引き継いで送信」で新しい thread に移る。最初の送信: 「第2往復の金額と、第3往復の期限を教えてください。」
5. 期待: Codex が台帳を読んで答える。
6. 控える: 正しく答えたか／台帳を読めなかったと言ったか。台帳ファイルがあるか（`%LOCALAPPDATA%\com.agentdock.app\chats\<チャット>\会話台帳.md`）。

### C2. K1: 想起試験（時間がかかるので任意）
1. 別の一般チャットで、第3〜5往復に固有の数値・人名を入れ、20往復ほど進める。
2. 次の3つの方法で、同じ質問（「第4往復の人名は？」）を比べる。
   (i) 引き継ぎ（台帳なし＝直近3往復のみ、設定で台帳が効かない場合）
   (ii) 同じ thread のまま、自動圧縮が起きたあと
   (iii) 引き継ぎ（台帳あり）
3. 控える: 各方法の正答／誤答。

### C3. K-D4・K-D5: 目的メモの下書きが `~/.codex` に影響しないか
1. C1 のチャットで、「…」メニュー →「目的メモの更新案を作る…」→「作成する」。
2. 期待: 下書き（決まったこと・前提・未解決・重要な数値、各項目に出典の往復番号）が出る。出典が台帳にない項目は「要確認」になる。内容を確認し、保存するかは任意。
3. 実行後、設定ファイルのハッシュを比べる。

4. 一時 thread が履歴に残らないか確認する（`~/.codex/sessions` の最新ファイル。読むだけ）。

## D. 直したばかりの画面

### D1. 右ペインの並び（確認 #12）
1. 状態不明（「履歴取得済み・live 未復旧」）の古いチャットを1つ選び、メッセージを送る。
2. 期待: 実行が始まったら、右ペイン「タスク」の**上のカードの先頭**に上がる。入力欄は空で、フォーカスを外した状態にする。
3. 作業中のチャットを6件以上にできれば、6件目以降が「ほかのタスク」に出る（「実行中」の印つき）。
4. 控える: 上がったか／上がらなかったか。上がらなかったら、そのチャットの「ヘッダーの表示」「左一覧のマーク」「入力欄の状態」。

### D2. 実行中の入力と送信キー（確認 #13）
1. 設定 →「入力」。「送信キー」は既定が **Enter**（保存済みの設定があればその設定）。「実行中の入力」で「完了後に送信」と「追加指示で送る」を切り替える。
2. 実行中のチャットで、Enter（送信キー）と Ctrl＋Shift＋Enter を押して、挙動が設定どおりか見る（「完了後に送信」＝キューに入る、「追加指示で送る」＝すぐ挟む。Ctrl＋Shift＋Enter は逆）。
3. 控える: 期待と違った組み合わせ。
