### 2. sandbox 健全性チェック

操作: 項目1を開始したときに、チェックが失敗する環境かどうかを見る（計画承認後・最初の Worker 送信前に実行される）。失敗しなければ「通った」でよく、2-B は不要。

2-A 失敗したとき（期待）:
- ワークフローは開始されず（Worker に送られない）、帯に「Codex の sandbox を起動できないため停止しています」。
- 画面にエラー帯で次の趣旨の案内: 「Codex の sandbox を起動できないため、組織実行を始めていません。原因の候補: Codex のプラグイン（node_repl／computer-use）と sandbox の更新が競合している（os error 32）。詳しくは %USERPROFILE%\.codex\.sandbox\ のログを確認…。回避: 設定 →「Codex」→「sandbox の競合を回避する」をオンにし、AgentDock を再起動してから「再開」。」
- 自動で再試行・自動回避されない。

2-B 回避オプション:
1. 設定 →「Codex」→「sandbox の競合を回避する（プラグインを無効にして Codex を起動）」をオンにして保存。「AgentDock の再起動後に有効になります」の表示が出る（現在の接続は再起動されない）。
2. AgentDock を完全終了→起動。
3. ワークフロー画面の「再開…」→ 確認「再開する」。
4. 期待: チェックを通り、Worker が進む。`~/.codex` のファイルを AgentDock が書き換えていない。
5. 確認後は設定をオフに戻す（プラグインを使う通常運用のため）。

要報告: 失敗しているのに案内文が出ない／案内が上と大きく違う／オンにしても通らない／再起動前に App Server が再起動された／チェック失敗なのに Worker へ送られた。通ったのに回避が必要になる場面があった場合は `diag.log` の org 行も添付。
sandbox・trust を turn なしで調べたい場合は `app/LIVE_CHECK_ORG4C.md` の A・B を参照（再掲しない）。

### 3. 差し戻し上限

操作: 差し戻しが起きやすい依頼にする（例: 「README.md に、必ず誤字を1つ含む1行を足す。レビューでは誤字を理由に不合格にすること」）。または Reviewer が不合格を出すまで通常の依頼で何度か試す。利用枠を使うので、再現しなければ ○ ではなく「未確認」でよい。

期待結果:
- Reviewer 不合格でタスクが `rework`（差し戻し）となり、試行が「2/3」のように増える。タスクごとの差し戻しは最大2回（試行3回）。
- 上限を超えるとそのタスクが「失敗（上限到達）」で止まり、利用者に引き継がれる（それ以上自動で差し戻さない）。依存するタスクは進まない。
- 再レビューは**新しいコミット**が対象になる（R-ORG M1 の修正。再レビューのたびに新しい Reviewer チャット）。

要報告: 3回目以降も自動で回り続ける／上限到達で何も表示されない／古い内容のまま合格になった。

### 4. 途中で完全終了→再起動→照合→再開

操作:
1. 項目1のワークフローを、Worker が実行中のときに用意する。
2. メニューの「終了」（トレイ含む）→ 終了確認ダイアログで「作業を中断して終了」を選ぶ。
3. 再起動して、ワークフロー画面を見る。
4. 「再開…」を押し、確認ダイアログの文面を読んでから「再開する」。

期待結果:
- 終了確認ダイアログに「**組織実行中**」の節（ワークフロー名・終わっていないタスク N 件（全 M 件））と「終了しても、再起動後に自動では再開しません。状態を照合したあと、『再開』を押したときだけ再開します。」が出る。
- 再起動後、帯「再起動前の状態を復元しました。『再開』で続けます」と、「再起動前に実行中だったワークフローを照合しました。再開するには『再開』を押してください。再開するまで、新しい送信はしません。」
- 照合（読取りのみ）はこの時点で自動で行われ、タスク表の下の注記に「照合（読取りのみ）: …」と作業場所（未コミットの変更の有無）が出る。**「再開」を押すまで新しい送信・新しい turn が始まらない**（チャットを見ても進まない。`events.jsonl` に新しい Dispatch が増えない）。
- 実行中だったタスクは `cancelled`／`failed` にならず「要照合」または「中断要求済み」「停止未確認」の確認状態で残る。
- 「再開…」の確認文: 「ワークフローを再開します。必要なチャットを Codex で再開（resume）し、止めていたタスクの送信を始めます。実行中だったタスクのチャットも再開して、その状態を受け取ります…確認できていないタスクは、確認できるまで送りません。」
- 「再開する」後に進み、終端を確認できたタスクは成果物の検証を通って完了する。再開できないチャットがあれば「…件のチャットは再開できず、そのタスクは送らずに止まっています」の通知。
- 計画の承認待ちの最中に終了→再起動した場合: 承認カードは再起動後も残り、「再開」では未承認のままタスクが動かない（H1 修正）。理由が失われたときは「理由は、再起動で失われたため表示できません…」と出る。

要報告: 再起動しただけでタスクが送られた／照合に「再開」が要った／終了確認に「組織実行中」が無い／タスクが完了・失敗に変わった／再開後に永久に止まるタスクがある（特にレビュー待ちで切断・再起動したもの。H2 修正の確認）。
注: 実行中の turn が無い時に終了すると確認ダイアログ自体が出ない可能性がある（推測。REVIEW_ORG L2）。その場合は実行中に試す。

### 5. 強制終了後の停止未確認

操作: 項目4の2で、終了確認ダイアログの「強制終了…」を押し、確認画面（「強制終了」）を読んでから「強制終了する」。再起動して画面を見る。

期待結果:

- 確認文に「…強制終了の後も、停止を確認できるまでは『停止未確認』として扱います。」

要報告: 強制終了後に取消し・失敗・完了と表示される／「組織実行中」が出ない／管理外の Codex まで止まった。

### 11. 役割定義

設定 →「組織実行」タブ。

操作・期待結果:
1. 初回: 標準3役（Planner・Worker・Reviewer）の定義ファイルが `%LOCALAPPDATA%\com.agentdock.app\org\roles\` に作られる（「標準の役割ファイルを作成しました: …」または開始時に作成）。各役割は「有効」で「基準の権限の範囲内です。」

```powershell
Get-ChildItem "$env:LOCALAPPDATA\com.agentdock.app\org\roles"
```

2. 既存ファイルは上書きされない: 例えば `worker.json` に末尾に空白だけ足して保存→「再読込み」→ 内容が保たれる（JSON を壊した場合は退避され問題一覧に出る。壊したままにしないこと）。
3. 権限を広げた定義: 役割ファイルのコピー（例 `worker2.json`、`id` も変える）で承認方針・sandbox・ネットワーク等を既定より広げ、「再読込み」。期待: その役割は「無効」で、「権限を広げている理由:」が列挙され、「この権限はまだ確認されていないため無効です。」
4. 有効化: 「有効化…」→ 確認ブロック「役割『…』の有効化の確認」（sandbox・承認の扱い・作業場所・ネットワーク・追加の書込み先・モデル等の表）→「この権限で有効にする」で有効に。Esc は確認だけを閉じ、設定全体は閉じない。確認後にファイルを書き換えて指紋が変わると有効化に失敗し、再読込みして再確認を求められる。
5. 「ファイルを開く」で関連アプリが開く。

注意（実装の制約）: 標準3役の ID 以外の役割は、この版ではタスクを実行できない可能性がある（REVIEW_ORG M4 の扱い。推測）。実行確認は標準3役で行い、広げた定義は表示・有効化の確認だけにとどめる。

要報告: 既存ファイルが上書きされた／広げた定義が無効にならない／理由が出ない／確認なしで有効になった。

### 12. trust の自動追記とworktree の後始末

目的: Codex 本体が worktree を新しい cwd として `~/.codex/config.toml` に `[projects.'<cwd>']`（`trust_level = "trusted"`）を追記する場合がある。AgentDock は config.toml を書かない。


2. 項目1の完了後に同じコマンドを実行し、増減を見る。増えた見出しを確認する。

```powershell
Select-String -Path "$env:USERPROFILE\.codex\config.toml" -Pattern '^\[projects\.' | Select-Object -Last 10
```

- trust 以外の差分（`[projects]` 以外の変更・削除）があれば「注意: …」の帯になる。その場合は要報告。
- `auth.json` に変化がない。

後始末:
- 見出しの名前が `agentdock-orgprobe-` を含むものだけ手で消してよい（許可済み）。それ以外のエントリは**勝手に消さない**（worktree の trust は残ってよい。消す場合は自分で判断して手で）。
