# DESIGN_MENUS — メニュー構成の整理と監視窓のショートカット（v0.1、2026-10-12）

対象: 上部メニューバー、各「…」メニュー、Ctrl+K、ショートカット、監視窓の開閉。
方針: **機能は削除しない**（移動・改名・グループ化・表示の修正のみ）。安全確認（削除・終了・強制終了・戻す・作業中アーカイブ等）の流れは変えない。新しい依存は入れない。見た目は UI-5 のトークンと既存の `.dropdown`／`Popover`／`.row-menu` を流用する。

## 2. 問題点

1. **分類が操作の種類で切れていない**: 「作業」15項目が区切り1本で並び、変更確認・会話操作・新規作成（worktree で開始）・管理（worktree を管理・クラウド委任）・入力設定（計画／実行の切替）が混在。「チャット」も作成・整理・一覧・アプリ終了が混在。
2. **見出しがない**: 区切り線だけで、何のまとまりか分からない。
3. **同じ操作で名前が違う**: ヘッダー「変更」「戻す」「分岐」⇔ メニュー「変更を確認」「変更を戻す…」「会話を分岐」。「ピン留めを切替」⇔「ピン留め／ピン留めを外す」。「MCP を確認…」「Plugins を管理…」⇔「MCP・Plugins…」。「終了済みも表示（全チャット）」⇔「…（完了・停止・確認済みの失敗）」。「コンパクト監視窓」⇔「監視窓」。左一覧の「表示 ▾」と上部「表示」が別物。
4. **「…」の付け方が不統一**: ダイアログを開くのに「…」がない（変更を確認、会話を分岐）、ヘッダーでは全部外れている。
5. **無効理由が見えない**: ヘッダー「…」はツールチップのみ。上部「チャット」は無効にならず押しても無反応。アーカイブと解除が両方常に出る。
6. **嘘のショートカット表示**: Ctrl+N・Esc。
7. **Ctrl+K が「すべての操作」になっていない**: 台帳の操作だけで、チャット管理・表示・設定は探せない。逆に Ctrl+K にしかない項目（利用状況、Codex の状態の別名3件）がある。
8. **仮置き項目**: ヘルプの2件がトーストだけ。
9. **監視窓のチェック表示が実接続で壊れている**、閉じる操作がアプリ内にない。
10. **危険操作の見分け**: 上部メニューの「削除…」「AgentDock を終了…」は通常色（行メニューでは削除が赤）。
11. 上部ドロップダウンにキーボードでの項目移動がない。

## 3. 新しい構成

### 3.1 統一規則（全メニュー・Ctrl+K・ツールチップ共通）

- **名前**: 動詞で終える「〜を…する」形（例「変更を確認…」「会話を分岐…」）。同じ操作（同じ act）は**どこでも同じ文字列**。短縮名（`header`）は廃止。
- **「…」**: 押すとダイアログ・確認・選択が出るものだけに付ける。即時に効くもの（ピン留め、ペイン切替、中断）には付けない。
- **状態つき項目**: オン／オフは ✓（`role="menuitemcheckbox"`＋`aria-checked`）。対になる操作（ピン留め／外す、アーカイブ／解除）は**1項目で今の状態に応じた文言**。
- **順序**: 見出しの中は「よく使う→まれ」。危険操作（削除・終了）は各メニューの最下段に区切って置き、赤（`.danger`、行メニューと同じ）。
- **無効**: 押せない項目は消さずに灰色で出し、**理由を項目の下に1行**（現在の作業メニューの `.has-why`／`.why` を全メニューへ）。ツールチップだけにしない。
- **ショートカット表示**: 右端に `.kbd`。**ハンドラーがあるものだけ**表示（§4.3 の一覧が唯一の出典）。
- **未確認・印**: 現在の `未確認` タグと `mark`（記録できません）は維持。
- **見出し**: グループの先頭に小さな見出し（`.menu-h`、`--fs-xs`・`--ink3`、操作不可、`role="presentation"`）。区切り線は見出しの前だけ。

### 3.3 各「…」の役割分担

|場所|役割|中身|
|---|---|---|
|ヘッダー「…」（label「このチャットの操作」）|**このチャット**でよく使う操作の近道|見出し「変更」: 変更を確認…／変更を戻す…／コードレビュー…　見出し「会話」: 会話を分岐…／Goal を設定…／状態を再照合（非liveのみ）　見出し「このチャット」: 作業フォルダの確認と変更…（開発のみ）／名前を変更…／ピン留め（外す）　─ すべての操作… Ctrl+K|

### 3.4 共通部品（新規ファイルなしで足りるなら既存へ）

- `ui/menuModel.ts`（新規）: メニュー定義を**データ**で持つ。
  ```ts
  type MenuEntry = { id: string } | { heading: string } | "-";
  interface MenuSpec { title: string; entries: MenuEntry[] }
  export const MENUBAR: MenuSpec[];          // §3.2
  export const HEADER_MORE: MenuEntry[];     // §3.3
  ```
- `ui/commands.ts` を拡張: `PARITY_COMMANDS` に加え `APP_COMMANDS`（チャット管理・表示・ツール・ヘルプ）を同じ `Command` 型で持ち、`commandViews` が両方の可否を返す。`Command` に `checked?(ctx)`・`danger?`・`keywords?`（検索用の別名）・`dynamicLabel?(ctx)` を追加。`header` フィールドは削除（`HEADER_MORE` に移る）。
- `ui/MenuList.tsx`（新規、小）: `CommandView[]`＋`MenuEntry[]` を受けて、見出し・区切り・✓・`.kbd`・`未確認`・`mark`・`.why`・`.danger` を描く。上部ドロップダウンとヘッダー「…」の両方で使う（行メニューは位置計算が別なので描画だけ揃え、`LeftPane` の既存 `.row-menu` を流用）。
- CSS: `.menu-h`（見出し）、`.pop .why`／`.pop button.has-why`（`.dropdown` 用の既存定義を `.pop` にも）、`.dropdown button.danger`。トークンのみ使用。

### 3.5 Ctrl+K との対応

- 項目は `PARITY_COMMANDS ∪ APP_COMMANDS` の全件（メニューにある操作は全部探せる）。名前はメニューと同一。
- 各行の右に所属メニュー名を小さく出す（例「作業」「チャット」）。検索は `label`＋`OP_LABEL`＋`keywords`（例: MCP・Plugins… に「MCP」「Plugins」、Codex の状態… に「速度」「Fast」「memories」「personality」）。
- 旧「速度（Fast）の設定を確認」「memories の設定を確認」「personality の状態を確認」の3件は、行き先が同じ「Codex の状態…」に統合（`keywords` で検索可能にするので到達性は落ちない）。能力表上の op（speedTier・memory・personality）は台帳から消さない（`OP_LABEL`・同等性ダイアログで使用）。※統合せず残すなら §6 要判断3。
- 無効項目も一覧に出し、理由を表示（現状どおり）。

## 4. ショートカット

### 4.1 監視窓

- **割当: Ctrl+Shift+M**（M = Monitor）。
  - 衝突確認: アプリ内で未使用（Ctrl+Shift+Enter のみ Shift 併用）。WebView2 の既定アクセラレーターにも該当せず、capture 段階で `preventDefault`。IME の切替キー（Ctrl+Shift・Alt+Shift・半角/全角）と同時押しでも `isComposing` 中は無視する。
  - Ctrl+Alt 系は使わない（AltGr 相当として扱う配列・IME ツールで干渉しやすい）。既存の Ctrl+Alt+B は変更しない。
- **動作（トグル、ホストで原子的に判定）**:
  - 監視窓がない／非表示／最小化 → 開く（なければ作る、最小化なら戻す）。**フォーカスは奪わない**（現行 `open_monitor` の方針どおり）。
  - 表示中（最小化でない） → 閉じる（窓を破棄。作業・収集・保存は継続、現行の×と同じ）。
  - 前面化だけ（開いたまま手前に出す）は、監視窓が最前面設定でない場合に「開く」で `show` しても前に出ないことがある。前に出すかは §6 要判断4。
- **どこで効くか**:
  - 通常画面: ダイアログ・Ctrl+K 表示中も有効（窓の開閉だけで画面状態を変えないため）。会話内検索欄・入力欄にフォーカスがあっても有効。
  - 監視窓の中: Ctrl+Shift+M で**監視窓を閉じる**（同じキーで開閉が往復できる）。
  - 通常画面がトレイ格納中: アプリ内キーは届かない。トレイ「監視窓を開く」を使う。**グローバルホットキーは入れない**（`tauri-plugin-global-shortcut` が新しい依存になるため。必要なら §6 要判断5）。
- **ホスト追加（P6 の窓管理に足す）**:
  - `toggle_monitor_window() -> bool`（操作後に開いているか）。`win::window::toggle_monitor(app, host)`: 窓あり＆可視＆非最小化→`close()`、それ以外→`open_monitor`。
  - `monitor_window_open() -> bool`（「表示」メニューを開いたときの ✓ 用。メニューを開くたびに1回呼ぶ。失敗時は ✓ なし＝不明として扱い、項目は押せる）。
  - `close_monitor_window()`（監視窓からの Ctrl+Shift+M 用。対象は `monitor` ラベルの窓だけ）。
  - 既存 `open_monitor_window` はトレイ・回答待ち案内用に残す。
- **名前の統一**: 「監視窓」に統一。メニュー「監視窓」、トレイ「監視窓を開く」（不変）、窓タイトル「AgentDock 監視窓」、通常画面の×のラベルは不変。`checked.toggleMini` は実接続では `monitor_window_open()` の結果を使う（モックは従来の `mini`）。

### 4.2 その他のショートカット修正

- **Ctrl+N**: 表示どおり「新しいチャット…」を実装（capture、`isComposing` 中は無視、ダイアログ・Ctrl+K 表示中は無効。WebView の新規窓より先に `preventDefault`）。
- **Esc（中断）**: 表示を外す。Esc はメニュー・検索・ダイアログを閉じるキーなので、中断に割り当てると誤操作で中断要求が出る（§6 要判断1）。
- 新規の割当は Ctrl+Shift+M と Ctrl+N の実装のみ。他は増やさない。

### 4.3 ショートカット一覧（唯一の出典 `ui/shortcuts.ts`）

```ts
export interface Shortcut { id: string; keys: string; label: string; where: "全体" | "通常画面" | "入力欄" | "検索" | "一覧" | "監視窓" | "ダイアログ"; act?: string }
export const SHORTCUTS: Shortcut[];
```

|キー|動作|場面|
|---|---|---|
|Ctrl+N|新しいチャット…|通常画面|
|Ctrl+K|すべての操作…|通常画面|
|Ctrl+F／F3／Shift+F3|会話内を検索／次／前|通常画面|
|Ctrl+B|チャット一覧の表示切替|通常画面|
|Ctrl+Alt+B|エージェントのドックの表示切替|通常画面|
|Ctrl+Shift+M|監視窓を開く／閉じる|通常画面・監視窓|
|Enter または Ctrl+Enter（設定による）|送信（実行中は完了後に送信）|入力欄|
|Ctrl+Shift+Enter|追加指示で送る（実行中）|入力欄|
|Ctrl+Enter|送信|side相談・編集して再送|
|Shift+F10／アプリケーションキー|行の操作メニュー|一覧|
|←→／Home／End／Enter|ペイン幅の調整／既定に戻す|仕切り|
|Esc|メニュー・検索・ダイアログを閉じる|全体|

- メニューの `.kbd` 表示、ツールチップの「（Ctrl+B）」、ヘルプの一覧はすべて `SHORTCUTS` から引く。キーの判定関数（`matchShortcut(e, id)`）も同ファイルに置き、App と MonitorApp のハンドラーはそれを使う。
- 単体テスト（純粋ロジックのみ）: ①メニュー・Ctrl+K に出る `kbd` はすべて `SHORTCUTS` に存在する ②同じ `act` に2つの名前がない ③`matchShortcut` が Ctrl+Shift+M／Ctrl+N／Ctrl+B と Ctrl+Alt+B を取り違えない・`isComposing` で false。

### 4.4 キーボード操作（メニュー自体）

- 上部ドロップダウン: 開いたら先頭の有効項目へフォーカス、↑↓ で移動（無効項目は飛ばす）、←→ で隣のメニューへ、Esc で閉じてメニュー名へフォーカスを戻す。`Popover` の実装を参照（同じ挙動）。
- アクセスキー（Alt+文字）は入れない（日本語名で文字を割り当てにくく、IME と干渉する）。

## 6. 要判断（ユーザーに選んでもらう点）

1. **中断のショートカット**: (a) なし（推奨。Esc は閉じる操作と衝突） (b) 入力欄にフォーカスがあり、メニュー・検索・ポップオーバーが開いていないときだけ Esc (c) 別キー（例 Ctrl+Shift+.）。
2. **ヘルプの仮置き2件**: (a) 最小実装（推奨: 状態の見方＝凡例の静的ダイアログ、バージョン情報＝AgentDock と Codex の版） (b) 実装するまでメニューから隠す。
3. **Ctrl+K の重複3件（速度・memories・personality → どれも「Codex の状態」）**: (a) 1件に統合し別名で検索可能に（推奨） (b) 現状どおり3件残す。
4. **Ctrl+Shift+M で監視窓が開いているとき**: (a) 閉じる（推奨。純粋なトグル、✓ と一致） (b) 前面に出す（閉じるのは×か監視窓内の Ctrl+Shift+M）。(b) の場合、前面化のためにフォーカスを一瞬移すかも併せて決める必要がある。
5. **グローバルホットキー**（トレイ格納中でも Ctrl+Shift+M）: (a) 不要（推奨。新しい依存 `tauri-plugin-global-shortcut` が要る） (b) 入れる。

## 7. 実機確認（ユーザー）

1. 上部メニュー5つを順に開き、見出し・区切り・危険色（削除・終了）が表示される。チャット未選択で「名前を変更…」等が灰色＋理由1行。↑↓←→ Esc で操作できる。
