# 段階② 実機確認の手順（ユーザー実施）

実際のCodex App Server・実認証・実推論を使うため、ユーザーが行う。利用枠を少量消費する。`~/.codex`は共有され、AgentDockは変更しない（確認0-3で前後hashを見る）。
通知・トレイ・自動起動・ダイアログは**NSISで導入したアプリ**で確認する（開発実行での通知表示は受入証拠にしない。正本§3.11）。

## 0. 準備

### 0-1. インストーラー

ビルド済みのインストーラー（司令塔がビルド）:

```powershell
Get-ChildItem C:\Users\wmasa\Documents\Rust\AgentDock_claude\app\src-tauri\target\release\bundle\nsis\*.exe
```

作り直すとき:

```powershell
cd C:\Users\wmasa\Documents\Rust\AgentDock_claude\app
npm run tauri build
```

`AgentDock_*_x64-setup.exe` を実行する（ユーザー単位の導入で管理者権限は不要）。署名なしのためSmartScreenが出たら「詳細情報→実行」。

### 0-2. 保存先

アプリのデータは `%LOCALAPPDATA%\com.agentdock.app\`（`chats\<dirId>\`・`settings.json`・`windows.json`・`diag\diag.log`）。段階①の開発実行でRoaming（`%APPDATA%\com.agentdock.app\chats\chat-*`）に作った作業フォルダは移動しない（使用量では「旧領域」）。

### 0-3. `~/.codex` の前後hash（最初と最後に実行して比較）

```powershell
Get-FileHash $env:USERPROFILE\.codex\config.toml, $env:USERPROFILE\.codex\auth.json
```

## 1. 確認項目（結果は○／×／気づきで一括報告）

### A. 保存と復元（P2）

|#|操作|期待|
|---|---|---|
|A1|チャットをピン留め、チャット別にモデル・effortを変える、入力欄に書きかけの文章を残してアプリを完全終了→再起動|ピン・モデル設定・下書きが戻る。下書きは**送信されない**|
|A2|新規の一般チャットを作る|作業フォルダが `%LOCALAPPDATA%\com.agentdock.app\chats\<dirId>\workspace` 配下|
|A3|（任意）`chats\<dirId>\chat.json` をメモ帳で壊して（先頭に `x` を足す）再起動|起動時に警告。元ファイルは `chat.json.corrupt-<数字>` として残り、上書きされない|

### B. 追加指示・完了後キュー（P3）

|#|操作|期待|
|---|---|---|
|B1|実行中に入力|切替が「完了後に送信」（初期値）。登録した依頼がキュー一覧に並び、送信前に編集・取消できる|
|B2|親が完了するまで待つ|登録順に1件ずつ自動送信。前の依頼のturnが終わるまで次は送らない|
|B3|サブエージェントを使う依頼の実行中にキュー登録|親が完了しても子・孫が作業中なら保留し、**対象と理由**が表示される。子孫が全部終わってから送る|
|B4|実行中に「追加指示（現在のturnへ）」で送る|受理が表示される（「反映」は会話の表示で確認、と案内。反映済みとは出ない）。拒否されたら「完了後に送信へ切り替える」が出て、添付も引き継がれる|
|B5|キュー登録中の依頼を中断（または失敗させる）|後続は送られず「キューは停止中」のバナー。「キューを再開」で残りが登録順に送られる。中断・失敗した依頼自体は再実行されない。「確認済み」を押してもキューは再開しない|
|B6|キューが残ったままアプリを完全終了→再起動|キューは「再起動後は停止中」で、**自動では送らない**。「キューを再開」で送る|
|B7|送信直後にcodexプロセスをタスクマネージャで終了|受理不明は「不明」と表示され、再送ボタンは出ない。再接続後に履歴との照合が続く（1分で打ち切らない）|
|B8|待機中の依頼があるときにモデル・権限を変える／作業フォルダを変える|待機中の依頼への影響が表示される。フォルダ変更は実行中はできず、確認のうえで変わる|

### C. 添付・成果物（P4）

|#|操作|期待|
|---|---|---|
|C1|ファイル選択・ドラッグ＆ドロップ・画像の貼付け（Ctrl+V）で添付|チップが出て送信前に外せる。フォルダは拒否される（作業フォルダの指定である旨）|
|C2|同じファイルを2回添付|別コピー・別添付（添付日時で区別）。元ファイルは変わらない|
|C3|画像とテキスト系ファイルを添付して送信|画像はアプリ内プレビュー。モデルが内容を読めたか（V09）を会話で確認。「表示できる」と「モデルが読める」が区別されている|
|C4|添付のコピー（`chats\<dirId>\attachments\...`）を手で消して会話を開き直す|「欠損」表示になり、その添付付きでは送れない|
|C5|ファイルを作らせる依頼|実在を確認した成果物だけがファイル項目に出る。「開く」で関連アプリ、「保存」は保存先を選べ、同名は上書き確認。生成だけで外部アプリは起動しない|
|C6|添付メニュー「選択範囲を貼り付け」（バッククォートを含む文章をコピーしてから）|コード枠付きで入力欄に入り、枠が途中で閉じない。過去会話の参考・Skill指定は出ない（段階③）|
|C7|添付付きで「完了後に送信」に登録|親完了後に添付付きで自動送信される|

### D. 通知（P5）

|#|操作|期待|
|---|---|---|
|D1|承認が出る依頼を、AgentDockを背後にして実行|承認待ちがすぐOS通知（チャット名と状態のみ。本文・コード・引数は出ない）|
|D2|子を複数使う依頼を背後で実行|子の完了・失敗が最初のイベントから**2秒**でまとめて1件の通知。失敗が完了に隠れない|
|D3|通常画面が前面で、選択中チャットのイベント|OS通知は出ない。別チャットのイベントは出る。監視窓だけ前面・最小化中なら出る|
|D4|通知をクリック|通常画面が前面に出て該当チャットが開く。承認・回答・再実行は起きない|
|D5|起動直後・再接続直後|過去の完了・失敗の一斉通知が出ない|
|D6|設定の「通知」タブで全体・種類別・音・チャット名表示を切り替える|反映される（名前オフで名前が出ない）|
|D7|子の失敗を起こす|左一覧に「失」の印（通知オフでも）。「確認済み」で外れ、再起動後も確認済みのまま。確認済みでもキューは再開しない|

### E. 窓・常駐・終了（P6）

|#|操作|期待|
|---|---|---|
|E1|窓の×|トレイに格納、確認は出ない。Codexの実行・通知は続く。トレイの左クリック／「開く」で同じ会話に戻る|
|E2|AgentDockをもう一度起動（スタートメニュー等）|2つ目は起動せず、既存の窓が前面に出る|
|E3|窓を動かす・リサイズ・最大化して再起動（R2のH1で修正した箇所）|落ちない。位置・サイズ・最大化が戻る。モニターを外した後は見える位置に戻る|
|E4|メニューの最前面（通常窓・監視窓それぞれ）|窓ごとに独立。オンにしてもフォーカスを奪わない|
|E5|メニュー「コンパクト監視窓」|別窓で開く。選択中チャット／全チャットを切替（初期は選択中）。カード選択で送信先・中断・承認は変わらない。「通常画面で開く」で該当チャットを開く。監視窓を閉じても作業は続く|
|E6|設定「ログイン時に起動」をオン→Windowsを再ログイン|通常画面を出さずトレイ格納で起動し、接続する。過去の依頼・キューは再実行しない|
|E7|作業中にトレイ／メニューから「終了」|作業中のチャットが示され「終了を取り消す／作業を中断して終了」。中断して10秒で停止を確認できなければ「待つ／中断を再試行／終了を取り消す」（停止確定とは出ない）|
|E8|E7から「強制終了…」|影響を受ける**全チャット**と対象が列挙され、未保存・処理残存の可能性の説明つきで確認。実行後、タスクマネージャでcodex関連プロセスが消えるか。確認できなければ停止未確認のまま|
|E9|PCをスリープ→復帰|鮮度が要照合→照合後に通知を受けたものだけliveに戻る。復帰で一斉通知や自動送信は起きない。キューはliveに戻るまで保留（理由表示）、「キューを再開」は押せる|
|E10|通知のアイコン・アプリのアイコン|仮の単色ではない|

### F. 削除・アーカイブ・エクスポート・使用量（P7）

|#|操作|期待|
|---|---|---|
|F1|作業中のチャットをアーカイブ|一覧から即座に消え、作業・通知・キューは続く。終了後に「Codex未反映」→反映済みへ。再起動を挟んだら「未反映」のままで、選び直すと再試行|
|F2|作業中のチャットを削除|確認に対象と「削除しないもの」が出る。中断→停止を確認できれば削除、10秒で確認できなければ「削除保留」。保留中は送信不可、再起動後も保留。停止確認後に「削除」を選び直したときだけ削除|
|F3|CLI・VS Codeで作った会話を削除|「一覧から外すだけ」。Codex側の履歴は残る（VS Code等で見える）|
|F4|Markdownエクスポート（「監視活動履歴も含める」あり／なし）|保存先を選べ同名は上書き確認。本文と添付・成果物のファイル名（中身は含まない）。ありのときは子・孫の活動が入る|
|F5|設定「保存と容量」|全体・チャット別・内訳・旧領域・空き容量が出る|
|F6|設定「Codex」の「参照…」|ファイル選択でcodex.exeを指定でき、再接続後に反映|

## 2. 実機で特に見てほしい点

- 子の「担当」が「未確認」のままか（段階①の観察。診断ログ `item-shape` でspawn itemの形）。
- `turn/steer` の受理と、Codexが追加指示を反映したか（会話の表示）。
- 通知のAUMID（`com.agentdock.app`）でトーストのクリックが届くか。
- 強制終了後にJob内のプロセスが0になるか、App Serverの再接続でキュー・受理不明・削除保留が引き継がれるか。
- sleep後に接続が生き残るか（生き残らない場合は再接続→照合→保留の流れ）。

## 3. 報告のしかた

項目番号ごとに○／×／気づきを書いて、×はエラー文または画面のスクリーンショット、必要なら `%LOCALAPPDATA%\com.agentdock.app\diag\diag.log` を添える。最後に0-3のhashを比べた結果も書く。Claudeが原因を切り分けて修正する。
