# ペット機能 設計メモ（提案・未実装）

2026-11-10。ChatGPT/Codexのペットと同じデータ形式で、作業状況の表示・通知・簡易入力を行う常駐の小窓。段階1〜5は実装済み（実機での確認は利用者が行う）。

## 合意事項
- ペットは `${CODEX_HOME:-~/.codex}/pets` を読み取り専用で参照する。コピー・変更しない。ペットの作成はCodexのhatch-petに任せる。
- 簡易入力の送り先は「最後に通知したチャット」が既定。入力欄に送り先を常に表示し、変更できる。
- 停止（中断）・削除・取り込みはペットから行わない。承認・質問への回答だけは、利用者の明示指示（2026-11-11）でペットから行える。回答は通常画面と同じホストの回答コマンドと、要求が示した選択肢そのものを使う（選択肢の追加・省略・自動回答をしない）。
- ペット窓のWebViewが呼べるコマンドは許可リスト（`visual_edit::preview::PET_COMMANDS`）だけ。表示・ペット自身の設定に加え、送信（`send_message`）と回答（`respond_request`）のみ。
- メイン画面の×は既存どおりトレイへ格納するだけなので、ペットは表示を続ける。トレイの「AgentDockを終了」で終了したときだけペットも閉じる。ペットの窓を閉じてもアプリは終了しない。

## データ互換（Codex V2）
- `pets/<フォルダ>/pet.json`: `displayName`、`description`、`spriteVersionNumber`、`spritesheetPath`。`id` は無い場合があるため、識別はフォルダ名で行う。
- 受け入れる条件: `spriteVersionNumber: 2`、PNG/WebP、1536×2288、8列×11行、1コマ192×208、背景透明。条件外（v1、1536×1872）は一覧に「非対応」と表示し、黙って捨てない。
- 行（コマ数・表示時間ms）。出典は hatch-pet の references/animation-rows.md。

| 行 | 動き | 列 | 時間 |
|---|---|---|---|
| 0 | idle | 0-5 | 280,110,110,140,140,320 |
| 1 | running-right | 0-7 | 120ずつ、最後220 |
| 2 | running-left | 0-7 | 120ずつ、最後220 |
| 3 | waving | 0-3 | 140ずつ、最後280 |
| 4 | jumping | 0-4 | 140ずつ、最後280 |
| 5 | failed | 0-7 | 140ずつ、最後240 |
| 6 | waiting | 0-5 | 150ずつ、最後260 |
| 7 | running | 0-5 | 120ずつ、最後220 |
| 8 | review | 0-5 | 150ずつ、最後280 |
| 9-10 | 16方向の目線 | 0-7 | 0°=上から時計回りに22.5°刻み |

- 正面（無方向）はidleへ戻す。動きを減らす設定のときは、idleの最初のコマだけを表示する。
- 選んだペット・位置・大きさはAgentDockの設定に保存する。

## 状態と動き
優先順位は、待ち > 失敗 > 完了 > 実行中 > 待機。材料は既存のHostEventとスナップショットだけで、監視のためのresume・追加の取得はしない。

| 状態 | 動き |
|---|---|
| 承認・質問待ち | waiting（即時） |
| 失敗・中断 | failed（停止未確認は失敗扱いしない） |
| 正常終了 | review → waving → 数秒でidle |
| 実行中 | running（複数でも1つにまとめる） |
| 待機 | idle。ときどき目線がマウスを追う |
| ドラッグ | running-left / running-right |
| クリック | jumping（1回） |
| 切断・状態不明 | idleに「状態不明」の印。完了とは表示しない |

- 子の完了・失敗は既存どおり2秒集約。親の完了だけで、子の停止や取り込み成功を断定しない。

## 画面の作り方（Tauri）
- 2つ目のウィンドウ `pet` を使う。透明・枠なし・最前面・タスクバー非表示。大きさは1コマ分に吹き出しの領域を足したもの。同じReactバンドルを表示モード切替で使い、HostEventを共有する。
- リスク（試作で先に確認する）:
  - Windowsでは、透明部分のクリックを下の窓へ通すことが、窓単位の切替でしかできない。カーソル位置による切替が必要。
  - 複数モニター・表示倍率の違いで、画面外へ出てしまう。起動時に画面内へ戻す。
  - 描画の負荷。ペット自体を「隠す」にしている間だけ描画を止める。メイン画面の最小化中や背面にある間は、表示も動きも続ける。

## 通知
- 完了・失敗・承認待ちを吹き出しで知らせる。押すと該当チャットを開く（既存の navigateToChat を使う）。
- ペットが見えている間は吹き出し、隠している間は既存のOS通知を使う。二重には出さない。

## 簡易入力（カード）
- ペットのクリックで小さなカードを開閉する（跳ぶ動きは維持）。窓はカード表示時に上へ広げ、閉じると戻す（足元固定、クリック透過の領域にカードを含める）。
- 送り先: 利用者が選んだチャット ＞ 最後に通知したチャット ＞ 通常画面で選択中のチャット。上部に常に表示し、最近のチャットから変更できる。
- 送信は通常画面と同じ `send_message`（ホストが送信不可条件を判定）。画面側も通常画面と同じ送信不可の理由（`sendLockReason`）で入力を止める。実行中は追加指示（steer）として送り、そう表示する。受理不明は送り先ごとに記録し、確認できるまでペットからは再送しない。送信後は「送信しました」。
- 返答: 送り先チャットの最新のエージェント発言を数行で表示する。ペット窓が受け取ったイベント分だけで、履歴の追加取得はしない（無ければ「まだありません」）。「チャットで開く」で通常画面へ。

## 承認・質問への回答
- 承認・質問待ちの吹き出しを押す、または回答待ちがあるときにペットを押すと、回答カードを開く。要求の内容（理由・コマンド全文・作業フォルダ・ファイル・追加権限・URL・サーバー・質問文）を省略せず、カード内スクロールで読める形で示す。
- 選択肢は要求が示したものをすべて、示された順に並べる。見た目だけ分ける（今回だけの許可＝主、会話・恒久の許可＝控えめな警告色、拒否・中止・その他＝枠線）。質問は選択肢だけの1件なら1回で確定、それ以外は全件そろってから「回答する」。
- 誤タップ防止: 要求が表示されてから0.5秒はボタンを押せない。回答済み・他の経路で解決済みになったらカードをすぐ閉じる。受理不明・届けられない場合はそのカードを無効にし、再送しない。
- 承認待ちの間は waiting の動きを保つ。「この会話の以降をすべて許可」は通常画面だけで、ペットにはない。

## 操作
- ダブルクリックでAgentDockを開く。吹き出しを押すとチャットを開く。
- 右クリックメニュー: AgentDockを開く、通知の一時停止（30分／1時間／再開）、大きさ（50・75・100・125・150%）、目線の追従オン／オフ（設定に保存、既定オン）、ペットの切替、隠す。
- 通知の一時停止は吹き出しとOS通知の両方を止める（保存しない。アプリを閉じると解除）。承認・質問（組織の承認待ち含む）は一時停止中も出す。
- 停止・削除・取り込みは対象外。

## 段階
1. 試作: 透明な最前面の小窓、クリックの透過、位置。
2. 表示: ペットの読み込み、動き、ドラッグ、目線。
3. 通知: 吹き出しとチャットを開く操作。
4. 簡易入力（カード）と、承認・質問への回答。
5. 操作メニュー（右クリック）。

各段階の前に、受入条件と確認方法を決める。
