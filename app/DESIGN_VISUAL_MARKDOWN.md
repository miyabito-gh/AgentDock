# Visual Editor Markdown対応 設計メモ（実装済み・実機確認待ち）

2026-11-11 提案、同日に段階1〜3を実装。HTMLのVisual Editorと同じ考え方（選ぶ → 依頼 → AIが元ファイルを直接直す → ターンごとに戻せる）をMarkdownにも使えるようにし、Markdownだけは利用者が自分で直す編集欄も付けた。実機（Tauri）での通し確認は未実施（ブラウザ上の部品確認は下記「確認の範囲」）。

## 合意事項
- Lumarkは無理に使わない。AgentDockの中に作る。Lumarkの小さな純粋関数（書式補助・安全処理）は、必要なものだけコピーし、出典（ファイル名・Lumarkの版）を記録する。アプリ連携・画面の埋め込みはしない。
- HTMLの直接編集は作らない（HTMLは現行のまま。変えたのは遅延読み込みと、ファイルを開く対象にMarkdownを足したことだけ）。
- 編集欄は「AIが作ったMarkdownを手直しする」用途に絞る。高機能エディタは入れない（標準の `<textarea>`）。
- 使っていないときに資源を使わない。

## 資源（実装）
- 画面のコードは遅延読み込み。`VisualGate`（`React.lazy`）が初めて開くまで `VisualWorkspace` を読まない。Markdownの画面（`MarkdownPane`、`marked`・`DOMPurify`・編集補助を含む）は、Markdownを開いたときに初めて読み込む。ビルドで `dist/assets` に別チャンク（`VisualWorkspace-*.js` 約80kB、`MarkdownPane-*.js` 約66kB、`VisualWorkspace-*.css`）として出る。入口のボタン・画面の枠・チャットの文脈表示に要るCSSだけは `visualShell.css` として本体に残した。
- **Markdownはプレビュー用のWebViewを作らない**（方式の選択）。画面の中で `marked`＋`DOMPurify` で描く。WebViewを作る案（HTMLと同じ `visual_edit/preview`）は、Markdownには重く、重なり順（メニュー・ダイアログとの重なり）の問題も増えるため採らなかった。HTMLを開いている間だけネイティブのWebViewを作る従来の動きは変えていない。
- ファイルの監視は編集欄が開いている間だけ（1秒ごと、画面が見えているときだけ。サイズと更新時刻を見る軽い確認）。閉じると止まる。
- Mermaid・PlantUMLは対象外。

## 画面
- 上: 操作列（ファイルを開く・ファイル名・状態・見出し一覧・表示切替［編集／並べる／表示］・保存・読み直す・場所）。幅が狭いときは縦に積む（コンテナクエリ）。
- 本体: 見出し一覧（任意）／編集欄（書式・検索の列つき）／プレビュー。下に行・列と文字コード・改行の表示。
- 下の依頼欄・会話・戻す/やり直す/差分はHTMLのVisual Editorと同じもの（`VisualEditControls`・依頼バー）。依頼の書き出しはMarkdown用（要約・簡潔に・表に・誤字）。
- 状態は平易な日本語で常に出す: 保存済み／未保存の変更あり／AIが編集中／依頼を送信中／保存中／外部で変更あり／ファイルが見つかりません／読み込めません。

## 描画
- `marked`（`Lexer`→トークンに元の行を付与→`Parser`＋`Renderer`継承）。見出し・段落・リスト項目・引用・コード・表・区切り線の開始タグに `data-src-start` / `data-src-end`（1始まり・両端を含む行番号）を付ける。行は、トップレベルのトークンの `raw` を連結すると元の文章になることを使って数え、リストの項目・引用の中は親の開始行から積み上げる（`render.ts`、テストあり）。
- `DOMPurify`（HTMLのみ、`style`・`class`・フォーム・埋め込みなどを除く）＋フック: リンクは `href` を外して移動させない（`data-href` 相当は持たず、`title` に宛先を出す。文書内の `#見出し` だけ移動）、画像は `data:` と文書フォルダ内の相対パスだけ（相対パスはホスト経由で読み、外部URLは読み込まず「表示しません」と出す）。チェックリストは表示だけ。
- 見出しのアンカーは Lumark の `createHeadingSlugger` 相当。

## 依頼（HTMLと同じ経路）
- プレビューのブロックを押して選ぶ（Ctrl/Shift＋クリックで複数、↑↓で移動、Escで解除）。依頼には「行の範囲＋本文の抜粋」を添える（`context.ts`）。`visualSendContext` と同じ印（`VISUAL_CONTEXT_MARK`）なので、チャット側の折りたたみ表示もそのまま使える。
- AIへ依頼を送る前（`begin` の中。依頼バーでも中央の入力欄でも通る）に、未保存の編集があれば「保存してから依頼する／送らない」を確かめる。保存しないなら依頼は送らない。
- 戻す・やり直す・差分・不一致確認は既存のターン単位の仕組み（`visual_edit/direct.rs`）をそのまま使う。スコープは「文書（編集可）＋文書から相対参照されるルート内の画像（読み取り専用）」（`host/visual.rs` の `discover_markdown`）。自分の保存はターンとして記録しない（`visual_markdown_save` は `turn_begin` を呼ばない）。
- 戻す対象のターンの後に自分で編集していた場合は、既存の不一致確認で止まり、上書きするかを確認する。

## 編集欄
- 保存（Ctrl+S／［保存］）。保存は読み込み時の印（サイズ＋更新時刻）と現在のファイルを比べ、違えば `conflict:` で拒否（利用者が「上書き」を選んだときだけ強制）。書き込みは `direct::safe_write`（リンク・外部への脱出を拒否、一時ファイル＋置換）。ターンの記録（`visual_rt.lock`）とは直列化。
- 文字コード・改行: **読込時にRust側で**BOMの有無・LF/CRLFを判定し（`visual_edit/markdown.rs`）、編集欄にはLFにそろえた本文を渡し、保存時に同じBOM・改行で書き戻す。LFとCRLFが混在していたら多いほうにそろい、その旨を表示する。壊れたUTF-8・NUL・4MB超は開かない（編集欄が出ず、理由を表示。上書きもしない）。
- 元に戻す・やり直す: 入力欄の標準（Ctrl+Z/Y）。書式・続け入力・インデント・置換は `document.execCommand("insertText"/"delete")` で入れるので、同じ履歴に残る（使えないときだけ代替の書き込みで、履歴は残らない）。
- 未保存の確認: Visual Editorを閉じる（ボタン）／別のファイルを開く／依頼の送信前は確認ダイアログ（`guard.ts` の窓口）。それ以外の経路（組織画面への切替など）で編集欄が消える場合は、未保存の内容をアプリの実行中だけ一時退避し（`draftStash.ts`）、同じファイルを開き直してファイルが変わっていなければ戻す。
- 外部での変更の検出: 1秒ごとにファイルの印を比べる。未保存がなければ自動で読み直し（通知を出す）、あれば「読み直す（編集は破棄）／自分の内容で上書き／別名で保存」を選ばせる。ファイルが消えたときは「この内容で保存し直す／別名で保存」。自分の保存の途中・直後は検出しない（世代番号で破棄）。
- AI実行中の制御: 編集に使う会話が実行中の間は、編集欄を読み取り専用にし「AIが編集中」と表示（保存・置換も止める）。ファイルの変化はその間も読み直して反映する。実行が終わったら読み直して編集欄とプレビューを更新する。依頼の送信中も、結果が決まるまで編集を止める。
- 位置の連動: プレビューのブロックを押すと編集欄の該当行へ移る（折り返しを含む行の位置は見えない複製で測る）。編集欄のカーソル行のブロックをプレビューが追う（並べる表示で、編集欄にフォーカスがあるとき）。
- 編集補助（`editing.ts` と Lumark からのコピー）: リスト・番号・チェックリスト・引用のEnterの続き入力と空項目での終了（番号は+1、チェックは未完了）、Tab／Shift+Tabのインデント（複数行・項目の子孫ごと）、Ctrl+B 太字・Ctrl+I 斜体・Alt+Shift+←／→ 見出しレベル・Ctrl+K リンクの挿入／編集、Ctrl+F 検索・F3／Shift+F3 次／前・Ctrl+H 置換（文字そのもの、大文字小文字の区別を選べる。一致は背面の複製で強調）、見出し一覧と移動（クリックで編集欄・プレビューがその行へ）。
- ショートカットの衝突: 編集欄（と、その検索・リンク欄）にフォーカスがあるときだけ、アプリ全体の Ctrl+K（コマンドパレット）・Ctrl+F（会話内検索）・Ctrl+B（チャット一覧）より編集欄を優先する（`inMarkdownEditor`＋`data-md-editor`）。それ以外のキー（Ctrl+N など）は従来どおり。`ui/shortcuts.ts` に「Markdown編集欄」として載せ、ヘルプの一覧に出る。Tab を文字として使うため、Esc で編集欄から出られる。

## Lumarkからコピーしたもの（Lumark 0.15.0、ファイル先頭に出典を記載）
- `lumark/markdownFormatting.js`（＋`.d.ts`、テスト`.test.mjs`）: 全体（太字・斜体・見出しレベル・行頭記号・リンクの編集）。
- `lumark/markdownStructure.js`（＋`.d.ts`、テスト`.test.mjs`）: `createIndentEdit`・`getMarkdownLineContexts`・`isInsideCodeFence` とその補助だけ（行の移動・複製・表のTab移動は除いた）。
- `lumarkSecurity.ts`（＋テスト）: `safeLinkTarget`・`normalizeLocalMarkdownPath`・`createHeadingSlugger`、および `safeExternalImageSource` を data: 画像だけに絞った `safeDataImageSource`（外部URLの許可を外した改変）。

## 対象ファイル
- `.md`、`.markdown`。ファイルを開く操作（OSの選択・チャット内のファイルメニュー「Visual Editorで開く」）でHTMLと一緒に選べる。名前が `AGENTS.md`・`CLAUDE.md` など、Visual Editorのパス規則（`RelativePath`）で除外されている名前は開けない。
- スコープ外のファイルをAIが作った・変えた場合は戻せない（HTMLと同じ。状態バーの説明にある）。

## 制限・あとで検討
- 実機（Tauri）の通し確認は未実施。ブラウザ（Edge）で部品の動き（描画・サニタイズ・キー操作・保存・外部変更・AI実行中・検索の強調・幅の狭いときの配置）は確認した。
- リンクはプレビューで開かない（宛先をツールチップに出すだけ）。外部の画像は表示しない。相対パスの画像だけ（5MBまで）。
- 番号付きリストの続き入力で、後ろの番号は振り直さない。表の編集補助（Tabでセル移動）、画像の貼り付け・挿入、自動保存、複数タブ、エクスポート、Mermaid・PlantUMLは入れていない。
- 検索は文字そのもの（正規表現なし）、5000件まで。4MBを超える文書は開かない。
- 編集欄の行数が非常に多い文書では、検索の強調（背面の複製）とプレビューの再描画（入力から0.2秒後）が重くなりうる。
- アプリを閉じるときの未保存の確認はWebViewの標準の確認（`beforeunload`）頼みで、Tauriの窓の閉じる操作では出ない可能性がある（一時退避は実行中のメモリだけなので、アプリ終了では失われる）。

## 段階（すべて実装済み）
1. 遅延読み込み（HTMLも含む）、Markdownのプレビュー・ブロック選択・依頼・ターン戻し。
2. 編集欄の基本（保存、未保存の確認、文字コード・改行の維持、外部変更の検出、AI実行中の読み取り専用、位置の連動）。
3. 編集補助（続け入力、インデント、書式ショートカット、検索・置換、アウトライン）。
各段階の最後にUI/UXの点検（既存画面との統一感・見やすさ・操作のわかりやすさ）を行い、見つけた問題は直した（コミットメッセージと最終報告に列挙）。

## 本体内描画の安全前提
Markdown は本体の画面（特権WebView）の中で描くため、次を前提にする。
- サニタイズ方針（`sanitize.ts`）: DOMPurify の html プロファイル。`area`・`map`・`usemap`・`ismap`・`id`・`name`・`style`・`class`・フォーム・埋め込みを除く。`a` は `href` を外して移動させない（クリックも `a,area` で止める）。`a`・`img` 以外の要素からは URL 属性（`href`・`xlink:href`・`src`・`action`・`formaction`・`poster`・`background` など）を除く。画像は `data:` とフォルダ内の相対パス（ホスト経由）だけ。`id`・`name` を除くのは、生HTMLが本体の要素（`getElementById` で引く id）と衝突しないようにするため（見出し移動は `data-slug`）。
- 遷移ガード（`nav_guard.rs`、Tauri プラグインの `on_navigation`）: label が `main`・`monitor`・`pet` のWebViewは、アプリ自身のURL（`tauri://localhost`、`http(s)://tauri.localhost`、`about:blank`、debugビルドだけ `http://localhost:5173`）以外へ遷移できない。拒否は diag に スキームとホストだけ記録。HTML プレビュー用の子WebView（label `visual-preview-*`）は対象外。
- CSP は未設定。既存画面への影響範囲が大きいため、今後の検討とする。
